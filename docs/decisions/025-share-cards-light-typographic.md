# 025. 공유 카드는 흰 바탕에 글자만으로 그리고, 받은 `card` 만으로 만든다

> 상태: 활성 · 결정일 2026-11-12 · 계획 태스크 8 · 결정 016 의 "공유 카드만 밤 바탕 + 차트 + 금" 과 결정 018 의 "공유 카드(밤 바탕)는 그대로다", DESIGN.md 의 "공유 카드(9:16): 밤 바탕, 차트" 줄을 대체한다. 서버 계약: 서버 저장소 결정 012(공유 카드 스냅샷). 번호 024 는 다른 작업 브랜치가 쓴다.

## 맥락
- 서버가 공유를 "공유하는 순간의 공개 글만 따로 저장" 하는 것으로 정했다(서버 결정 012). `POST /shares` 가 `{ shareId, card }` 를 주고, 공개 조회 `GET /shared/{shareId}` 는 그 `card` 만 준다. `card` 에는 출생 정보·차트·근거가 없다.
- 결정 016 의 카드는 밤 바탕에 차트(가는 선과 금 점)를 그리는 것이었다. 그런데 공유 페이지는 세션 없이 열리고 차트를 받지 않는다. 카드에 차트를 넣으면 앱에서 만든 이미지와 링크로 연 페이지의 카드가 달라지고, 차트 자체가 출생 정보에서 나온 값이다.
- 화면은 결정 018 로 흰 바탕·중립 회색·초록 하나가 됐고, 밤 바탕은 카드에만 남아 있었다.
- 서버에는 내 이름이 없어 궁합 점수 카드의 내 이름을 공유할 때마다 받아야 한다(서버 결정 012 의 6).
- 지금 앱은 켜질 때 루트 레이아웃이 세션을 시작한다(개발용 세션이 켜져 있으면 `POST /auth/dev`). 공유 페이지도 그 아래에 있다.

## 결정
1. **카드는 `card` 에 있는 값만으로 그린다.** 차트 그림을 넣지 않는다. 앱의 미리보기·저장되는 이미지·공유 페이지가 같은 부품(`features/share/share-card.tsx`) 하나로 같은 내용을 그린다. 카드에 더하는 것은 앱 이름과 한 줄 소개(문구 파일)뿐이다.
2. **모양은 화면과 같은 디자인 시스템(결정 018)이다**: 흰 바탕, 중립 회색 글씨, Pretendard, 카드 모서리. 초록은 카드 머리의 짧은 줄 하나에만 쓴다. 비율은 9:16. 밤 바탕과 금은 쓰지 않는다(`Colors.night`·`nightGold` 는 쓰는 곳이 없어졌다. 지우는 것은 따로 한다).
3. **이미지**
   - 앱(iOS·Android): 카드 뷰를 `react-native-view-shot` 의 `captureRef` 로 1080×1920 PNG 파일로 만들고 `expo-sharing` 의 시스템 공유 시트로 보낸다. 링크는 React Native `Share` 의 시스템 공유 시트로 따로 보낸다 — `expo-sharing` 은 파일 하나만 받고, 파일과 글을 한 번에 보내는 방법이 iOS 와 Android 에서 다르기 때문이다. 그래서 버튼이 둘이다("이미지 공유" · "링크 공유").
   - 웹: `react-native-view-shot` 의 웹 구현은 `html2canvas-pro` 를 쓰는데 배율을 정할 수 없어 작은 미리보기를 늘린 흐린 이미지가 된다. 그래서 웹에서는 `html2canvas-pro` 를 직접 불러 가로 1080 이 되는 배율로 그린 뒤 PNG 로 내려받게 한다("이미지 저장"). 링크는 `expo-clipboard` 로 복사한다("링크 복사").
4. **공유 주소**는 `<웹 주소>/s/<shareId>` 다. 웹 주소는 `EXPO_PUBLIC_WEB_URL`, 없으면 웹에서는 지금 주소의 origin. 둘 다 없으면(앱에 변수가 없을 때) 링크 버튼을 누를 수 없게 둔다.
5. **내 이름은 공유할 때 묻는다.** 궁합 점수 카드의 시트가 먼저 "내 이름"(앞뒤 공백을 뗀 1~20자)을 받는다. 마지막에 적은 이름은 앱이 켜져 있는 동안 메모리에만 두고 기기 저장소에는 두지 않는다.
6. **공유는 시트를 열 때 만든다.** 화면을 여는 것만으로는 `POST /shares` 를 부르지 않는다. 랭킹 카드의 "이름 그대로 보이기" 는 꺼진 채로 시작하고, 바꾸면 카드를 다시 요청한다(서버가 이니셜을 만든다. 앱은 이름을 줄이지 않는다).
7. **공유 페이지(`/s/<shareId>`)에서는 세션을 시작하지 않는다.** 루트 레이아웃이 첫 경로 조각이 `s` 인 동안 세션 시작을 건너뛴다. 이 페이지가 부르는 것은 세션 헤더 없는 `GET /shared/{shareId}` 하나다. "나도 보러 가기" 로 `/` 에 가면 그때 세션이 시작된다.
8. **`Reading.shareId` 는 읽지 않는다.** 응답 검사(`isReading`)가 이 필드를 요구하지 않는다(서버 결정 012 의 4 — 서버가 응답에서 뺄 수 있게).

## 대안
- 밤 바탕 + 차트(결정 016 그대로) — 공유 페이지에 차트가 없어 이미지와 페이지가 달라진다. 차트를 `card` 에 실으면 출생 정보에서 나온 값이 공개된다.
- 웹 이미지를 캔버스에 직접 그리기(글자 배치를 손으로) — 의존성은 없지만 카드 모양이 두 벌이 되어 서로 어긋난다.
- 웹에서는 링크만 — F6 이 웹에 "이미지 저장" 을 요구한다.
- 내 이름을 기기에 저장 — 편하지만 계정에 없는 개인 값을 기기에 남긴다. 소셜 로그인이 들어와 서버가 이름을 갖게 되면 묻지 않게 바꾼다.
- 공유 페이지를 루트 레이아웃 밖의 다른 뼈대로 — Expo Router 에서 루트 레이아웃은 하나라 글꼴 적재까지 두 벌이 된다.

## 결과·재검토 조건
- 프로덕트 디자이너가 카드 모양을 다시 잡으면 `share-card.tsx` 와 `theme.ts` 의 카드 값만 바꾼다. 차트를 다시 넣으려면 서버의 `card` 에 무엇을 실을지부터 정해야 한다.
- 링크 미리보기(메신저에 붙였을 때의 제목·설명)는 공유 페이지의 고정 문구다. 카드 내용을 미리보기에 넣으려면 서버 렌더링에서 `GET /shared/{shareId}` 를 불러야 한다 [확인 필요].
- 공유 지우기(`DELETE /shares/{shareId}`)는 호출만 있고 화면이 없다.
- 소셜 로그인이 붙어 로그인 가드가 생기면 `/s/` 를 그 가드의 예외로 둔다(F7 "로그인 없이 열리는 화면은 공유 페이지뿐").
