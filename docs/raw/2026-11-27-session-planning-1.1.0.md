# 2026-11-27 1.1.0 기획 시작 — 범위 (소유자 말 · 세션 제안)

> 원본이다. 고치지 않는다. 정리본: 앱 결정 100(docs/decisions/100-scope-1.1.0.md).
> 상황: 1.0.0 은 iOS 심사 중, 안드로이드는 비공개 테스트 14일 중. 이 세션은 코드를 건드리지 않고 기획 문서 · 결정(ADR) · 시안만 한다(소유자).

## 소유자가 준 범위
- "별명 1.1.0 기획을 시작하자. … 궁합(나의 사람들), 광고와 자세한 풀이 유료화, 방향성 · 음악을 넣을지 정하는 게 범위야. 먼저 docs/product.md, docs/release-1.0.0.md, 결정 010 · 055 · 069 를 읽고 1.1.0 범위와 순서를 제안해 줘."

## 세션이 읽고 짚은 것
- 015 의 광고 대상(요약 해석 · 심층 리포트 · 궁합 리포트 · 방향성)은 050 · 063 뒤로 대부분 없다. 008 의 방향성 VIP · 014 의 "리포트 계속 무료" 는 050 이 뒤집었다.
- 방향성: 이성 · 미래는 048 · 049 가 없앴고, 궁합 방향성은 063 이 결과 안 "이 사이의 작은 실천" 으로 넣었다 → 따로 남길 기능이 없다(없애기 제안).
- 서버에는 결제 확인 자리(`EntitlementPolicy`, 402 `PURCHASE_REQUIRED`)와 옛 궁합 경로(`/synastry/direct` · `/synastry/ranking` · `/synastry/{id}/report`)가 있다.

## 묻고 답한 순서
1. 소유자: "내가 생각했을 땐 광고, 인앱 결제, 음악 이것만할까 뭐가 있으면 좋을까"
   - 세션: 좁히기는 찬성(친구창 · 투두 · 그룹 궁합은 1.2.0 이후). 셋만이면 "빼앗기만 하는 판"(무료 풀이 → 유료 + 광고, 새로 생기는 건 음악뿐)이고, 풀이가 유료가 되면 광고가 오늘의 하늘 · 그날의 하늘 앞에 붙는다. 사용자가 거의 없을 때 광고 · 결제 수익은 작다. 추천: 셋 + 궁합 직접 입력판.
2. 소유자: "광고를 하지말까?"
   - 세션: 1.1.0 에는 하지 않기를 추천. 수익은 사용자 수에 비례하는데 지금은 거의 없고, 광고 하나에 SDK · 서버 확인 · 처리방침 · 두 스토어 신고 · 추적 허용 창 · 만 14~18세 맞춤 광고 끄기 · 990원 상품 · 구매 복원이 따라온다. 음악과 소리 겹침도 사라진다. 다시 볼 조건을 붙인다.
3. 소유자: "음.. 다시 정리해보자"
   - 세션: 후보 표와 세 판 — A 결제 + 음악 / B A + 궁합 직접 입력판(추천) / C A + 궁합 전체(링크 · 웹 진입 · 카카오).
4. 소유자: "C가 나을 것 같은데"
   - 세션: C 로. 링크 묶음을 맨 뒤에 만들어 밀리면 그것만 1.1.x 로 넘기는 "자를 선" 제안.
5. 소유자: "안드로이드 출시되면 웹은 없앨 예정이긴한데"
   - 세션: 그러면 063 의 웹 진입(로그인 → 출생 정보 → 사이 → 결과)을 빼고, 앱이 없으면 랜딩의 "앱 받기" 페이지로. iOS 는 설치 뒤 이어 가기 기본 방법이 없어(Firebase Dynamic Links 종료) "앱을 받은 뒤 이 링크를 다시 눌러 주세요" 로 시작. 웹 종료 자체는 따로 결정(애플로 가입한 웹 사용자가 안드로이드폰이면 들어갈 길이 없음 · 옛 공유 링크 `/s/…` · 웹 사용자 안내 · 037 · 070 · 072 · 077 정리).
6. 소유자: "광고 없애자 그럼" / "근데 메시지 유료 아닌가? 카카오 메시지?"
   - 세션: 063 의 "카카오톡 공유"(사용자가 자기 카톡에서 골라 보냄)는 앱별 쿼터 안에서 무료. 유료는 알림톡 · 친구톡(비즈메시지). 쿼터 상향 신청은 2026-04-01 에 닫힘(재공지 예정). 출처: https://developers.kakao.com/docs/ko/kakaotalk-share/faq · https://devtalk.kakao.com/t/api-change-in-how-to-increase-kakao-talk-share-api-quota/147734
7. 소유자: "웹없애는 건 나중에 생각하자"
   - 세션: 1.1.0 은 웹이 있든 없든 같게 기획(링크 → 앱 받기 페이지, 웹에서 유료 풀이는 "앱에서 받기" 안내만).
8. 소유자: "그리고 공지사항도 만들어야할 것 같은데??"
   - 세션: 서버 · 어드민 · 앱에 공지사항이 없다(확인). 자주 묻는 질문(결정 028)과 같은 틀로 범위에 넣고, 보이는 곳은 시안에서.

10. 소유자: "유료 풀이(나 탭 · 시기, 따로 · 묶음) 이거 같이 통합으로 해서 990으로 하려고 하는데 어때 1990원으로 할까"
    - 세션: 하나로 묶기는 찬성(상품 하나 · 비소모성 · 계정에 묶음, 화면은 지금처럼 따로). 가격은 1,990원 추천 — 앱의 긴 글 전부를 990원에 주면 싸 보이고, 올리기는 어렵고 내리기는 쉽다. 중간안: 정가 1,990원 + 출시 기념 한동안 990원. App Store 원화 가격 목록에 990 · 1,990 이 있는지는 확인 못 함. 함께 정할 것: 1.0.0 에서 하나라도 받은 계정은 둘 다 열어 주기(추천), 출생 정보를 고친 뒤 다시 받기는 무료, 사람당 AI 비용 확인.
11. 소유자: "그렇게 하자 정가 1990원에 하고 한 달간 990원으로 하자"
12. 소유자(결정 101 을 1,990원 · 990원으로 쓰는 중에): "아닌가 4990 원으로 하고 한동안 1990원으로 할까"
    - 세션: 정가 4,990원 + 출시 한 달 1,990원도 낫다(할인 여지 · 다시 받기 비용). 단 "한동안" 은 날짜로 정하고 끝나면 실제로 4,990원을 받아야 한다(받은 적 없는 정가에 줄 긋기는 표시광고 문제 소지 — "출시 기념가 · 한 달 뒤 4,990원" 처럼 사실만).
13. 소유자: "우리 가격 을 측정해보자"
    - 세션(코드로 추정, 서버 로그는 이 세션 권한 밖): 운영 모델 claude-opus-5-5 · effort medium(입력 $4 · 출력 $20 / 100만 토큰). 나 탭 풀이 = 모델 5번(칩마다), 시기 풀이 = 시기 9개씩 묶어 2~3번. 한 사람 원가 약 1,300~1,600원(넓게 800~2,300원, 1달러 1,400원 가정). 손에 남는 돈(부가세 · 수수료 15% 뺌): 990원 → 약 765원(손해), 1,990원 → 약 1,540원(본전), 4,990원 → 약 3,860원. 포스텔러 원화 가격은 검색으로 못 찾음(앱스토어 "앱 내 구입" 목록에서 직접 보기).
14. 소유자: "출 시 한 달 2990으로 할까 그럼"
    - 세션: 좋다 — 2,990원이면 손에 약 2,310원, 원가가 높게(약 2,300원) 나와도 본전. 1,990원은 첫 달 판매 수를 노릴 때.
