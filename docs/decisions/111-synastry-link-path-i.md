# 111. (1.1.0) 궁합 링크 주소는 `/i/<코드>` 다 — 옛 공유 링크 `/s/<공유번호>` 는 그대로 둔다

> 상태: 활성 · 결정일 2026-11-28(소유자 "엉 바꾸자")
> - 결정 104 의 링크 주소(`byeolmyeong.com/s/…` · 웹 이어 보기 `app.byeolmyeong.com/s/…`)만 대체한다. 104 의 나머지는 유효하다.
> - 시안: 캔버스 "궁합 (1.1.0)" 링크 칸 · 링크 메뉴 · 새 링크 · 메신저 미리보기 · 초대(주소 글자만 바뀜)
> - 원본: docs/raw/2026-11-27-session-planning-1.1.0.md 183 ~ 184

## 맥락
- 1.0.0 의 공유 링크는 `app.byeolmyeong.com/s/<공유번호>` 이고, 앱에 같은 라우트 `src/app/s/[shareId].tsx`(결정 025 · 053)가 있다.
- 104 는 궁합 링크를 `byeolmyeong.com/s/…` 로 그렸다. 도메인은 다르지만 두 곳에서 겹친다.
  1. 앱은 링크를 받으면 경로만 보고 라우트를 고른다. 궁합 링크가 앱을 열면 옛 공유 카드 화면으로 가서 "없는 공유"가 된다.
  2. 웹 이어 보기 주소 `app.byeolmyeong.com/s/…` 는 옛 공유 페이지와 똑같다.

## 결정
1. 궁합 링크 주소는 `byeolmyeong.com/i/<코드>` 다(i = 초대). 웹 이어 보기는 `app.byeolmyeong.com/i/<코드>`, 앱 라우트는 `/i/[code]` — 세 곳 모두 같은 경로.
2. 옛 공유 링크 `app.byeolmyeong.com/s/<공유번호>` 와 앱 라우트 `/s/[shareId]` 는 그대로 둔다(이미 보낸 링크가 계속 열린다).
3. 아이폰 유니버설 링크: 랜딩에 `/.well-known/apple-app-site-association` 을 두고 `/i/*` 만 앱으로 넘긴다. 다른 랜딩 페이지와 `app.byeolmyeong.com` 은 브라우저에서 열린다. 앱은 associated domains `applinks:byeolmyeong.com` 을 더한다(새 빌드). 안드로이드 앱 링크는 안드로이드 출시 때.
4. 분석: 화면 이름은 경로 패턴 `/i/[code]` 로만 보내고 코드는 보내지 않는다(040 의 3). `app_opened` 의 entry 는 `/i/[code]` 면 `invite`.

## 근거
- 경로를 나누면 앱 · 웹 · 분석 어디서도 두 링크를 구분하는 분기(도메인 보기)가 필요 없다.
- 옛 링크를 지우지 않아 1.0.0 사용자가 보낸 공유가 깨지지 않는다.

## 대안
- `/s/` 를 그대로 쓰고 앱이 도메인으로 갈라 보내기: 앱 · 웹 · 분석에 분기가 생기고, 웹 이어 보기는 같은 도메인이라 여전히 겹친다.
- 옛 공유 페이지 `/s/` 를 지우고 궁합에 넘기기: 이미 보낸 링크가 깨진다.

## 결과
- 시안 5장의 주소 글자와 설계 메모 3개를 `/i/…` 로 고쳤다. 피그마 v1.1 의 같은 보드도 고친다.
- 구현 계획: S③ 링크 코드 경로 · L① 랜딩 페이지와 유니버설 링크 파일 · A 줄 associated domains.
