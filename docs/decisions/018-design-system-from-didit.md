# 018. 화면은 디딧 프론트의 디자인 시스템(색·글꼴·부품)으로 다시 만든다

> 상태: 활성 · 결정일 2026-11-11 · 결정 016 의 색·글꼴·부품 모양을 대체한다. 016 의 "차트를 눈금 원과 가는 선으로" 와 공유 카드(밤 바탕)는 그대로다.

## 맥락
- 결정 016 의 값으로 만든 입력 화면을 소유자가 웹에서 직접 써 보고 "전체적으로 이상하다"고 판단했다(2026-11-11). 한 줄짜리 선 입력칸, 각진 버튼, 화면 안에 펼쳐지는 선택 목록이 쓰기 불편했다.
- 소유자가 기준으로 든 것은 디딧 프론트(`ddiddit/didit-frontend`)의 디자인 시스템이다(그 저장소의 `DESIGN.md`·`app/components/ui/`). 버튼·입력칸·체크박스·하단 시트·드럼롤 선택 같은 부품의 모양과 동작을 그대로 따르기로 했다.
- 색은 처음에 "모양은 디딧, 포인트만 금색"을 골랐다가, 같은 날 "색상이랑 전부 다 가져오자"로 바꿨다. 주색도 디딧의 초록을 쓴다.

## 결정
- 바탕은 흰색, 글씨·선·채움은 중립 회색 팔레트, 글꼴은 Pretendard 하나. 주색은 초록(`#3DDB99`) 하나이고 주 버튼·선택 표시·포커스 테두리에 쓴다. 고른 칩의 바탕은 옅은 초록(`#ECFBF5`).
- 부품: 높이 56·모서리 12 의 채운 입력칸(라벨은 위, 도움말·오류는 아래), 높이 56·모서리 12 의 가운데 정렬 버튼, 체크 표시 체크박스, 모서리 12 의 선택 칩, 아래와 양옆이 화면에 붙고 위쪽 모서리만 24 로 둥근 하단 시트(위에 손잡이 줄, 뒤의 막은 서서히 어두워지고 시트만 올라온다, 위쪽을 잡고 끌어내리면 닫힌다). 디딧의 시트 부품은 화면에서 떠 있지만 소유자가 붙이기로 했다, 드럼롤 선택.
- 고르는 입력은 하단 시트에서 한다: 태어난 시각은 오전/오후·시·분 드럼롤, 태어난 곳은 시·도 → 시·군·구 칩.
- 넓은 웹 화면에서는 가운데에 앱 화면 폭 390 한 단만 보인다. 그 밖은 흰색이고 옅은 선으로 나눈다.
- 값의 단일 출처는 그대로 `src/constants/theme.ts`, 원칙과 금지 목록은 `DESIGN.md` 다.

## 버린 대안
- 모양은 디딧, 포인트만 금색: 처음 골랐으나 소유자가 바꿨다. 남는 걱정: 다른 서비스의 주색과 같아진다. 브랜딩(앱 이름, 결정 013) 때 주색을 다시 본다.
- 모양만 바꾸고 종이색·명조는 유지: 소유자가 고르지 않았다.

## 영향
- `src/components/` 의 `Button`·`Field`·`Checkbox`·`Sheet`·`Screen` 을 다시 만들고 `Chip`·`ScrollPicker` 를 더한다. 고운바탕·IBM Plex Mono 글꼴 패키지를 뺀다.
- 디자인 보드(docs/design/design-system-v2.png·key-screens-v2.png)는 옛 방향이다. 프로덕트 디자이너가 새 방향으로 다시 만든다.
- 디딧 프론트 저장소에는 라이선스 표시가 없다. 코드는 옮기지 않고(그쪽은 Vue, 여기는 React Native) 치수·동작만 참고해 새로 작성했다. [확인 필요] 소유자가 그 저장소의 권리자인지.
