# 069. 음악(결정 062)은 1.0.0 에서 빼고 1.1.0 에 넣는다 — 코드는 남겨 꺼 둔다

> 상태: 활성 · 결정일 2026-11-20(소유자 "1.0.0 에는 음악을 넣지 않는다", "1.1.0 에 넣는다 — 궁합과 같은 묶음", 세션 67 경유) · 결정 062(음악 세 곡)의 **시기만** 1.1.0 으로 미룬다 — 세 곡 · 스위치 셋 · 휴대폰 규칙 · 웹 규칙은 062 그대로 · 계획 `docs/plans/2026-11-20-sian-all-repos.md` 의 A⑨

## 맥락
- 062 에 따라 음악 줄(`features/audio`) · 무음 자리표시 셋(`assets/audio/`) · 마이 › 음악 화면(`/my/music`)을 만들어 develop 에 넣었다(PR #48). 진짜 음원은 아직 없고, 루트에 거는 두 줄(배경 · 스플래시)은 걸지 않았다 — 그래서 지금 앱은 소리를 내지 않는다.
- 소유자는 1.0.0 을 음악 없이 내고, 음악은 궁합과 함께 1.1.0 에 넣기로 했다.

## 결정
1. 1.0.0 에서는 소리가 나지 않는다: 루트에 `useSoundtrackRoot()` · 스플래시의 `useSoundtrack('opening')` 을 걸지 않는다. 마이 첫 카드에 "음악" 줄을 두지 않는다.
2. 이미 들어간 코드는 지우지 않고 꺼 둔다: `features/audio`(음악 줄 · 설정 · 훅) · `assets/audio/` · `expo-audio` · `expo-asset` · 별명 짓는 중의 `useSoundtrack('waiting')`(루트가 없으면 아무것도 하지 않는다) · 음악 화면.
3. `/my/music` 은 주소로 바로 들어와도 마이(`/my`)로 보낸다 — 스위치가 아무 일도 하지 않는 화면을 보이지 않게. 켜고 끄는 곳은 `features/audio/tracks.ts` 의 `MUSIC_IN_APP` 하나다.
4. 1.1.0 때 다시 켤 일(이 목록이 그때의 할 일이다):
   - `MUSIC_IN_APP` 을 true 로 — `/my/music` 이 열린다.
   - 루트 레이아웃에 `useSoundtrackRoot()` 한 줄, 스플래시에 `useSoundtrack('opening', 스플래시가 떠 있는 동안)` 한 줄.
   - 마이 첫 카드 맨 위에 "음악" 줄(`strings.my.rows` 에 다시 더함, 결정 056 의 2 순서: 알림 · 음악 · 자주 묻는 질문 · 문의하기).
   - 새로 생긴 쓰는 중 화면(나 탭 풀이 · 시기 풀이 · 오늘의 하늘 쓰는 중)에 `useSoundtrack('waiting')`.
   - 진짜 음원 셋을 `assets/audio/` 에 같은 이름으로(그 README) — 크기 · iOS 웹 음량(코드로 못 바꿈) 확인.
   - 새 개발 빌드로 기기에서 확인: 무음 스위치 · 다른 앱 소리와 섞임 · 뒤로 갔다 돌아옴 · 웹의 첫 누름.

## 근거
- 음원이 없고 기기 확인을 못 한 채 1.0.0 에 넣으면 소리 버그가 첫인상을 해친다. 코드를 지우면 1.1.0 때 다시 만들어야 하니, 꺼 둔 채 둔다.

## 대안
- 코드를 지운다 — 1.1.0 때 다시 만들고 리뷰해야 한다. 고르지 않았다.
- `/my/music` 을 그대로 열어 둔다 — 아무 소리도 안 나는데 스위치만 있는 화면이 된다. 고르지 않았다.

## 결과·재검토 조건
- 결정 062 앞머리에 "시기는 069 로 1.1.0" 표시를 단다. 1.1.0 에서 위 4 의 목록을 끝내면 이 결정은 대체된다.
