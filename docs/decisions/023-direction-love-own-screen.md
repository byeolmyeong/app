# 023. 방향성 "이성" 은 따로 화면(`/direction`)으로 두고, 요약 해석 아래에는 들어가는 줄만 둔다

> 상태: 활성 · 결정일 2026-11-12 · docs/release-1.0.0.md "화면" 표의 "방향성 제시 — 요약 해석·심층 리포트 "시기"·궁합 결과 화면 안" 중 이성 주제만 바꾼다. 결정 022 의 "연애에서 해 볼 만한 것 → 준비 중" 줄을 대체한다. 번호 021 은 다른 작업 브랜치가 쓰고 있다.

## 맥락
- F10 은 방향성 "이성" 이 놓이는 곳을 "요약 해석(F3) 아래" 로 정했고, 화면 표는 방향성 제시를 "요약 해석 화면 안" 으로 적었다. 계획 태스크 12 도 화면 안에 넣는 부품(`DirectionCard`)을 가정했다.
- 서버 계약(`POST /directions`, 서버 결정 009)은 처음 만들 때 기다렸다가 답한다. 실제로 재 보니 17초쯤 걸린다. 요약 해석 화면 안에서 바로 부르면 요약 해석을 읽으러 온 사람마다 글 생성이 한 번 더 일어나고, 화면 아래쪽이 그동안 "짓는 중" 으로 남는다.
- 결정 019 · 022 는 홈 "관계" 칸에 "연애에서 해 볼 만한 것" 항목을 두고 기능이 생기면 열기로 했다. 홈에서 바로 가려면 갈 주소가 있어야 한다.

## 결정
- 방향성 "이성" 은 따로 화면 `/direction` 에서 보여 준다: 한 줄 제목 → 해 볼 만한 것 3개(항목마다 근거 줄 · 제목 · 본문, 요약 해석의 문단과 같은 모양) → 안내 문구. 기다리는 상태와 실패했을 때의 "다시 시도" 를 갖는다.
- 요약 해석(`/reading`)에는 글 아래에 `/direction` 으로 들어가는 줄 하나만 둔다("이성은 요약 해석 아래" 를 이 줄로 지킨다). 요약 해석 화면은 `POST /directions` 를 부르지 않는다. 글 생성은 사용자가 화면을 열 때만 일어난다.
- 홈 "관계" 칸의 "연애에서 해 볼 만한 것" 은 `/direction` 으로 간다.
- 받은 글은 요약 해석처럼 출생 정보별로 기기에 두고, 있으면 서버를 부르지 않는다(같은 차트 = 같은 글. 서버에 다시 생성하는 방법이 없다).
- 미래 · 궁합 주제는 이 결정의 범위가 아니다. 붙을 화면(리포트 시기 · 궁합 결과)을 만들 때 같은 방식으로 할지 정한다.

## 버린 대안
- 요약 해석 화면 안에 바로 그리기(F10 · 화면 표의 원안) — 열 때마다 글 생성이 하나 더 일어나고, 홈 "관계" 칸에서 바로 갈 주소가 없다.
- 요약 해석 화면 안에서 "보기" 를 누르면 그 자리에 펼치기 — 생성 호출은 미룰 수 있지만 홈에서 가는 길이 요약 해석을 거쳐야 하고, 화면 하나가 두 글의 대기 · 실패 상태를 함께 갖게 된다.

- docs/release-1.0.0.md "화면" 표에 `/direction` 줄을 더한다. 서버 계약은 바뀌지 않는다.
