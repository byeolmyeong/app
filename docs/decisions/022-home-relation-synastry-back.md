# 022. 홈에 관계 · 궁합 칸을 다시 올린다

> 상태: 활성 · 결정일 2026-11-11 · 결정 019 의 "2026-11-11: 관계 · 궁합 칸을 홈에서 뺐다" 줄만 대체한다. 019 의 나머지(네 칸의 구분, 아이콘 타일, 시트, 준비 중 표시, 아래 탭)는 그대로다.

## 맥락
- 결정 019 는 홈을 나 · 관계 · 궁합 · 시기 네 칸으로 정했다가, 같은 날 소유자 요청("일단 빼자")으로 관계 · 궁합 칸을 뺐다. 조건은 "그 기능들이 만들어질 때까지" 였다.
- 직접 입력 궁합(F5 의 앞 절반: 입력 · 점수 · 겹친 휠 · 리포트 · 랭킹)을 만들면서 소유자가 두 칸을 다시 올려 달라고 했다(2026-11-11).

## 결정
- 홈의 카테고리는 나 · 관계 · 궁합 · 시기 네 칸이고 이 순서로 한 줄에 놓는다.
- 관계 칸의 항목: "사람을 대하는 성향" → 심층 리포트의 관계 영역(`/report?area=RELATIONSHIP`), "연애에서 해 볼 만한 것" → 아직 없다(방향성 "이성", F10). 준비 중으로 둔다.
- 궁합 칸의 항목: "상대와 궁합 보기" → `/synastry`, "궁합 랭킹" → `/synastry/ranking`.
- 019 의 "홈에서 특정 영역으로 바로 가는 항목은 없다" 는 관계 칸의 한 항목에 한해 바뀐다. 심층 리포트의 관계 영역은 "나 → 심층 리포트" 의 탭으로도 그대로 본다.

## 버린 대안
- 궁합 칸만 올리고 관계 칸은 방향성 "이성" 이 생길 때 올린다 — 소유자가 두 칸을 함께 요청했다. 관계 칸의 한 항목(사람을 대하는 성향)은 이미 있는 화면으로 간다.

## 영향
- `src/content/strings.ts` 의 `main.categories`, `src/features/home/home-categories.tsx`(아이콘 둘 · 갈 수 있는 경로), 홈 화면 테스트.
- docs/release-1.0.0.md "화면" 표의 홈 줄. 서버 계약은 바뀌지 않는다.
