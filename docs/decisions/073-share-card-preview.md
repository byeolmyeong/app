# 073. 공유 카드는 화면에 들어올 때 저장 없는 미리보기로 받아 두고, 공유할 때만 공유를 만든다

> 상태: 활성 · 결정일 2026-11-21(소유자 — "공유 카드 미리 받기를 되살림", 세션 67 경유) · 결정 053 의 3("시트를 열 때 `POST /shares` 를 한 번")에 덧붙인다 · 서버: 서버 결정 051(`POST /shares/preview`, api PR #52)

## 맥락
- 공유 시트를 처음 열면 `POST /shares` 를 기다리는 동안 카드 자리에 뼈대가 보였다. 미리 받으면 서버가 공유하지 않은 사람의 공개 글을 저장하게 되어(서버 결정 012 "공유하는 순간만 저장") 하지 않았다.
- 서버가 저장하지 않는 미리보기 길(`POST /shares/preview` — 요청은 `POST /shares` 와 같고 응답은 `{ card }` 뿐, 공유 행 · 식별자 · 감사 기록 없음)을 만들었다.

## 결정
1. 공유 아이콘(또는 버튼)이 있는 화면에 들어오면, 로그인이 확인된 뒤 그 카드를 `POST /shares/preview` 로 받아 기기의 카드 기억(`share-cache`)에 둔다 — 시트를 처음 열어도 바로 카드가 보인다.
2. 기억하는 종류(내 별명 · 나 탭 영역 · 그날의 하늘 · 다음 큰 변화)만 미리 받는다. 궁합 카드는 내 이름 · 이름 표시에 따라 달라 받지 않는다.
3. 미리 받기가 실패해도 받아 둔 카드를 지우지 않는다. 같은 카드는 기기 기억의 세대(로그아웃 · 계정 삭제 · 출생 정보 바꾸기가 지운다)마다 한 번만 받는다.
4. 실제로 공유할 때(시트를 열 때)는 지금처럼 `POST /shares` 로 만든다(결정 053 의 3 그대로).

## 근거
- 저장이 없는 길이라 서버 결정 012 의 "공유하는 순간만 저장" 을 지키면서 첫 열기를 빠르게 할 수 있다.

## 결과·재검토 조건
- 서버 PR #52 가 develop 에 들어가기 전에는 미리보기가 404 라 조용히 넘어간다(이 실행에서 그 카드를 다시 부르지 않는다).
