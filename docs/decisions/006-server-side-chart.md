# 006. 차트 계산은 서버에서 한다

> 상태: 활성 · 결정일 2026-11-10 · docs/decisions/003-chart-engine-astronomy-engine.md 를 대체한다

## 맥락
003 은 로그인도 서버도 없는 작은 범위를 전제로 차트를 기기 안에서 계산하기로 했다. 그 뒤 1.0.0 범위에 궁합 초대, 리포트, 푸시 알림, 횟수 제한이 들어왔다(docs/release-1.0.0.md). 사용자가 계산은 서버에서 해야 한다고 정했다.

## 결정
행성 위치·하우스·각도·변곡점 연도·출생 시각의 표준시 변환을 모두 서버(서버 저장소, Kotlin)에서 계산한다. 앱은 출생 정보를 보내고 받은 차트를 그리기만 한다. 차트 계산 요청은 로그인 없이 받고, 로그인하지 않은 사람의 출생 정보는 저장하지 않는다.

## 근거
- 궁합 초대에서 상대의 생년월일은 나에게 보이면 안 된다. 행성 위치만으로도 생일을 역산할 수 있어서, 두 차트를 겹치는 계산은 서버에서만 할 수 있다.
- 리포트는 사용자가 화면을 떠난 뒤에도 서버가 쓰고 알림을 보낸다. 서버가 차트를 갖고 있어야 한다.
- 서버가 직접 계산하면 앱이 보낸 수치를 검사할 필요가 없고 조작된 수치로 글을 받을 수 없다.
- 계산 오류를 스토어 심사 없이 서버 배포만으로 고친다.
- 한국의 옛 표준시와 서머타임 이력은 JVM 의 시간대 데이터가 기기마다 다른 런타임보다 일관된다.

## 대안
- 기기 안 계산(003) — 즉시 표시되고 인터넷이 없어도 되지만 위 근거의 첫 두 가지를 풀지 못한다.
- 양쪽 모두 계산 — 같은 계산을 TypeScript 와 Kotlin 에 두면 결과가 어긋난다.

## 결과·재검토 조건
- 차트 화면에 인터넷이 필요하다. 받은 차트는 기기에 보관해 다시 열 때는 요청하지 않는다.
- 로그인 없는 계산 요청은 남용될 수 있다. 서버에서 요청 수를 제한한다.
- 계산 라이브러리: Swiss Ephemeris 의 라이선스 문제(AGPL)는 그대로다. astronomy-engine 의 Kotlin 판을 쓸 수 있는지 서버 작업을 시작할 때 확인한다. [확인 필요]
- 앱 저장소 계획의 태스크 2·3·4(행성 위치, 하우스·각도, 출생 시각 변환)는 서버 저장소 계획으로 옮긴다.
- 기준값: NASA JPL Horizons 에서 받은 세 시각의 행성 황경을 서버 테스트에 쓴다(받은 값은 docs/raw/2026-11-10-jpl-horizons-reference.md).
