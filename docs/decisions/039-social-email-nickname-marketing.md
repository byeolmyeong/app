# 039. 소셜 로그인에서는 이메일만 필수로 받고, 가입 화면에서 닉네임과 마케팅 수신 동의(선택)를 받는다

> 상태: 활성 · 결정일 2026-11-19(소유자) · 결정 034 의 카카오 웹 `scope=openid` 를 대체 · 서버 쪽: 서버 결정 021 의 "이메일 · 이름은 받지 않는다" 를 대체하는 서버의 새 결정(번호는 서버 저장소가 정한다) · 계획: docs/plans/2026-11-19-social-email-nickname.md

## 맥락
- 결정 034 와 서버 결정 021 은 공급자의 사용자 식별자(`sub`)만 받았다. 공개된 처리방침(https://byeolmyeong.com/privacy, 2026-11-19)도 "이메일 · 이름 · 프로필 정보는 받지 않습니다" 다.
- 소유자(2026-11-19): 서비스 안내와 소식 · 마케팅 메일을 보낼 주소가 필요하다. 소셜에서는 **이메일만, 필수로** 받고, 닉네임 · 생년월일 · 태어난 시각 · 태어난 곳은 가입(온보딩)에서 받는다. 첫 마케팅 메일은 출시 뒤.
- 정보통신망법 제50조: 광고성 정보는 수신자의 명시적 사전 동의를 받아야 보낸다. 동의 · 철회의 처리 결과를 알리고(시행령 제62조의2), 2년마다 수신 동의 여부를 확인한다(시행령 제62조의3).
- 공급자가 주는 이메일:
  - 구글: 기본 범위의 ID 토큰에 `email` · `email_verified` 가 든다.
  - 애플: `email` 범위를 요청해야 ID 토큰에 든다. 사용자가 "이메일 가리기" 를 고르면 릴레이 주소(`…@privaterelay.appleid.com`)가 온다.
  - 카카오: 동의항목 "카카오계정(이메일)" 과 `account_email` 범위가 있어야 OIDC ID 토큰에 든다. 소유자가 비즈 앱으로 전환하고 **필수 동의**로 켰다(2026-11-19).

## 결정
1. **소셜에서 받는 것은 공급자가 확인한 이메일 하나다.** 이름 · 프로필 사진은 받지 않는다.

   | 공급자 | 웹 | iOS | Android |
   |---|---|---|---|
   | 구글 | 그대로(기본 범위에 이메일이 있다) | 그대로 | 그대로 |
   | 애플 | Apple JS `scope: 'email'` | `requestedScopes: [EMAIL]` | 없음(결정 034) |
   | 카카오 | 인가 주소 `scope=openid account_email`(034 의 `scope=openid` 대체) | 네이티브 SDK — 콘솔 동의항목(필수)을 따른다 | iOS 와 같음 |

2. **앱은 공급자가 준 이메일을 읽어 서버로 따로 보내지 않는다.** 서버가 ID 토큰에서 확인한 값만 쓴다. 새 사람인데 확인된 이메일이 없으면 서버가 `EMAIL_REQUIRED` 로 가입을 막고, 앱은 로그인 화면에 "이메일 제공에 동의해야 가입할 수 있어요" 류의 안내를 공급자 이름 없이 보여 준다.
3. **가입 화면(`/signup`)은 한 화면**이다: 닉네임(필수) · 출생 정보(결정 020 · 029 그대로) · "(선택) 소식 · 혜택 메일 받기" 체크박스(기본 꺼짐). 닉네임은 앞뒤 공백을 뗀 1~20자, 줄바꿈 · 제어 문자 금지, 중복 허용(아이디가 아니라 부르는 이름). 판정은 서버가 하고, 앱은 같은 규칙으로 먼저 안내만 한다.
4. **마이(결정 038)** 맨 위 카드에 닉네임(바꿀 수 있음) · 이메일(읽기만)을 두고, "알림 · 수신" 줄에 마케팅 메일 스위치를 둔다. 동의 · 철회할 때마다 앱 안에 처리 결과(전송자 "별명" · 일시 · 동의/철회)를 보여 준다.
5. 궁합 공유 카드의 "내 이름" 칸은 닉네임으로 미리 채운다(바꿀 수 있고 서버 공유 계약은 그대로).
6. 이메일 · 닉네임은 기기 저장소 · 로그 · 분석 이벤트에 두지 않는다. 서버가 원본이다.
7. 넣지 않는 것: 메일 발송 기능과 2년 수신 동의 확인 안내(첫 마케팅 메일 전에 따로 계획), 이메일 바꾸기 화면(이메일은 공급자에서만 온다), 같은 이메일의 다른 공급자 계정 합치기.

## 근거
- 소셜 로그인에는 비밀번호가 없어 연락 수단이 이메일뿐이다. 이메일 하나만 받으면 수집 항목이 가장 작다.
- 서버가 토큰에서 확인한 값만 믿으면 앱을 고쳐 남의 주소를 넣을 수 없다.
- 마케팅 수신을 가입 필수와 묶으면 법이 요구하는 "별도 · 선택" 동의가 아니다.

## 대안
- 이메일 선택 동의 — 소유자가 필수를 골랐다.
- 공급자 닉네임 받기 — 실명 · 별명이 섞이고 동의항목이 늘어난다. 가입 화면에서 직접 받는다.
- 이메일을 앱에서 입력받기 — 인증 메일 절차가 필요하고, 공급자가 이미 확인한 값이 있다.

## 결과·재검토 조건
- 처리방침(랜딩)을 이메일 · 닉네임 · 마케팅 동의에 맞게 고친 뒤에 이메일을 받기 시작하는 배포를 낸다.
- 카카오 범위를 넓힌 배포는 카카오 동의항목 설정 뒤에만 낸다(설정됨, 2026-11-19). 반대 순서면 카카오가 로그인을 막는다.
- 애플 릴레이 주소로 메일이 가려면 애플 개발자 콘솔 Email Sources 에 보내는 도메인 · 주소를 등록해야 한다(첫 메일 전).
- 이 변경 전에 이메일 범위 없이 애플로 승인한 계정은 이메일을 다시 묻지 않을 수 있다 — 있는 계정은 이메일 없이도 로그인된다.
