# 앱 1.0.0

> 상태: 승인(태스크 1~3 먼저 실행) · 기준 2026-11-10 · 이전 계획 docs/plans/2026-11-10-mvp.md 를 대체한다(그 계획의 태스크 1 은 완료됐다). 서버 쪽 계획: `../byeolmyeong-api/docs/plans/2026-11-10-api-mvp.md`

## 목표
- 무엇을: docs/release-1.0.0.md 의 기능 F1~F9 를 웹·iOS·Android 에서 쓸 수 있는 앱.
- 누구를 위해: 자기 이해 콘텐츠를 즐기는 한국어 사용자.
- 끝나면: 입력 → 차트 → 로그인 → 내 별명 → 심층 리포트 → 궁합 초대 → 공유 → 계정 삭제가 한 벌의 코드로 세 플랫폼에서 된다.

## 결정된 전제
- 기능·화면·출시 기준: docs/release-1.0.0.md
- 디자인: docs/design/screens-1.0.0.html (도장과 책력, Pretendard)
- 차트 계산은 서버: docs/decisions/006-server-side-chart.md · 로그인: docs/decisions/005-google-apple-login.md · Expo: docs/decisions/001-expo-single-codebase.md
- API 계약: 서버 저장소 `../byeolmyeong-api/docs/architecture.md` "API 계약"
- 규칙: docs/golden-rules.md, AGENTS.md(Expo 규칙)

## 내 결정 (묻지 않고 고른 기본값)
- 서버가 준비되기 전에도 화면을 만들 수 있게, API 응답 예시(JSON)를 `src/lib/fixtures/` 에 두고 테스트와 개발용 가짜 서버가 함께 쓴다.
- 화면 문구는 `src/content/strings.ts` 한 파일에 모은다. 이유: 1.1.0 에서 영어를 붙인다.
- 받은 차트와 글은 기기에 보관해 다시 열 때 요청하지 않는다.
- 어두운 화면 모드는 만들지 않는다.

## 승인 메모 (2026-11-10, 사용자)
- 태스크 1~3 을 먼저 실행한다. 4번부터는 외부 준비(로그인 클라이언트 등록 등)가 필요하다.
- 화면 디자인은 프로덕트 디자이너가 전부 다시 작업한다. 그래서 지금은 시안(docs/design/screens-1.0.0.html)을 기능이 보이는 수준으로만 옮기고 다듬지 않는다. 색·글자·간격을 `src/constants/theme.ts` 한 곳에, 부품을 `src/components/` 에 모아 나중에 통째로 바꿀 수 있게 한다.
- 디자이너에게 주는 설명: docs/design/designer-brief.pdf

## 범위 밖
- docs/release-1.0.0.md "1.0.0 에 넣지 않는 것" 전부.
- 스토어 제출 자체(빌드·심사 요청). 제출 준비물까지만 한다.
- 차트 계산. 서버가 한다.

## 전역 제약
- 패키지 설치는 `npx expo install <패키지>` 만. Expo·EAS·React Native API 는 쓰기 전에 공식 문서를 확인한다(AGENTS.md). Node 22.
- 색·글자·간격은 `src/constants/theme.ts` 의 값만 쓴다. 화면에 색 값을 직접 적지 않는다.
- 화면 문구를 컴포넌트에 직접 적지 않는다. `strings.ts` 에서 가져온다.
- 세션 토큰·출생 정보를 로그와 분석 이벤트에 남기지 않는다.
- 새 동작은 실패하는 테스트를 먼저 본다. 화면은 웹에서 열어 콘솔 에러 0 과 폭 390px 레이아웃을 스크린샷으로 남긴다.

## 리뷰 초점
1. 시각 "모름" 사용자가 지나는 모든 화면에 하우스·상승궁이 새어 나오지 않는가 (태스크 3·5·6).
2. 로그인 시트를 닫거나 로그인에 실패했을 때 하려던 동작이 조용히 실행되거나 화면이 멈추지 않는가 (태스크 4).
3. 초대 링크를 로그인하지 않은 사람이 앱 없이 웹에서 열었을 때 수락까지 갈 수 있는가 (태스크 7).
4. 서버가 느릴 때 버튼을 여러 번 눌러 요청이 중복되지 않는가 (태스크 5·6·7).
5. 계정 삭제 뒤 기기에 남은 차트·글로 화면이 다시 그려지지 않는가 (태스크 10).

## 자동 반복
- 하지 않는다. 화면 확인이 기준에 들어 있어 사람이 봐야 한다.

## 위험 · 되돌리기
- 서버 계약과 fixtures 가 어긋날 수 있다. 서버 태스크가 끝날 때마다 실제 응답으로 fixtures 를 바꾼다.
- 웹과 Android 의 애플 로그인이 Expo 에서 번거로울 수 있다. 태스크 4 에서 공식 문서로 방법을 정하고 막히면 보고한다.
- 작업은 태스크별 브랜치에서 한다. 태스크 하나 = 커밋 하나.
