# 113. (1.1.0) 홈 메뉴판 · 탭 다섯을 앱에 옮길 때 비어 있던 것 — 새로워진 점은 "1.1.0 이 처음 켜질 때 소개 기록이 이미 있던 기기"에만, 궁합 탭은 A④ 전까지 빈 하늘

> 상태: 활성(제안 — 소유자 확인 전) · 결정일 2026-11-28(1.1.0 계획 A① 을 구현하며 세션이 고름 — 계획 "결정이 문서에 없으면 더 단순하고 되돌리기 쉬운 쪽") · 결정 102(홈 · 탭 다섯) · 104 의 12(들어오는 길 · 소개 세 장) · 109 의 6(새로워진 점 창)이 구현에 맡긴 빈칸을 채운다. 대체하는 결정은 없다.
> - 시안: 캔버스 https://claude.ai/artifact/Rt33TzPSEe4PdxNRCej3xT "홈 (1.1.0)" 의 A · 온보딩 소개 2/3 · R3, "궁합 (결정 104)" 의 1-2

## 맥락
- 109 의 6: 새로워진 점 창은 1.1.0 을 처음 켤 때 한 번, **1.0.0 에서 업데이트한 사람만** 본다. 앱은 1.0.x 에서 "몇 판을 썼는지" 를 기기에 적지 않았다. 앞으로 결제(101)와 함께 생길 서버의 `GET /entitlements`(서버 S1-3)는 아직 없다.
- 셋째 줄 "받았던 자세한 풀이는 그대로" 는 1.0.0 에서 받은 사람에게만 보인다(109 의 6).
- 102 의 1-4: 홈의 연애 · 친구 궁합은 사이가 켜진 입력 화면으로 간다. 입력 화면 · 궁합 탭의 별 지도는 A④(서버 S② 뒤), 내 궁합 링크는 A⑥ 이다. A① 은 서버 없이 먼저 간다.
- 102 의 4: 1.0.0 홈의 "이번 달 미리 받기"(075 의 4)를 시기 탭을 빨리 열려고 남길지는 구현 때 정한다.

## 결정
1. **새로워진 점 창을 띄울 기기**
   - 1.0.x 가 기기에 남긴 소개 기록(`byeolmyeong-device.introSeen.v1`, 결정 042)으로 가린다. 1.0.x 를 켠 기기는 첫 실행에 소개를 보며 이 값을 적었고, 로그아웃 · 탈퇴가 지우지 않는다.
   - 1.1.0 의 새 기록 `byeolmyeong-device.whatsNew110.v1` 이 없으면 이 기기에서 1.1.0 이 처음 켜진 것이다. 그때 **이번 실행이 소개를 적기 전의** 소개 기록을 본다(소개 기록을 처음 읽은 값 — 소개 화면은 그 값을 읽은 뒤에야 뜬다).
     - 있었다: 1.0.x 에서 올라온 기기. 로그인한 홈이 처음 다 그려진 때 창을 띄운다. 닫기 · 궁합 보러 가기를 누르면 "봤음" 을 적는다.
     - 없었다: 새로 깐 기기. 곧바로 "새 기기" 를 적는다 — 소개만 보고 끈 새 사람이 다음 실행에 창을 보지 않게.
   - 저장소를 읽지 못하면 띄우지 않는다(새 사람의 첫 화면을 막지 않는 쪽). 새 기록도 기기 값(`byeolmyeong-device.`)이라 로그아웃 · 탈퇴가 지우지 않는다.
   - 웹도 같은 규칙이다(브라우저 저장소의 소개 기록). 웹의 1.0.0 사용자도 바뀐 홈을 처음 본다.
   - 한계: 1.0.x 를 받고 한 번도 켜지 않은 기기, 앱을 지웠다 다시 깐 기기는 새로 깐 것으로 본다.
2. **셋째 줄은 앱이 지금 아는 값으로 가린다.** 창을 띄울 때 나 탭 풀이나 시기 풀이가 다 쓰인 상태면 보인다 — 기기에 받아 둔 것을 먼저 보고, 없으면 홈이 앱을 켤 때 묻는 상태(`GET /me-report` · `GET /timing-report`)로. 창은 둘 다 알 때까지 기다린다(못 물었으면 줄 없이).
   - 1.1.0 을 처음 켠 순간에는 아직 결제할 길이 없다(결제는 1.1.0 앱 안에서만, 웹 결제 없음 — 101 의 7). 그래서 그때 다 쓰인 풀이는 1.0.0 에서 받은 것이다.
   - 서버 `GET /entitlements` 가 생기면 `LEGACY` 로 바꿀 수 있다(제안 — A③ 에서 다시 본다).
3. **궁합 탭(`/synastry`)은 A④ 전까지 0명 화면(시안 1-2)의 별 지도 카드만 그린다.**
   - 그 아래 "첫 궁합을 볼 사람이 있나요?" 와 두 줄(직접 입력 · 내 궁합 링크 보내기)은 갈 화면(입력 A④ · 링크 A⑥)이 생길 때 켠다. 누를 곳 없는 줄은 두지 않는다.
   - 홈 나의 사람들 두 줄은 지금 궁합 탭으로 옮기고 사이를 주소에 싣는다(`/synastry?relation=LOVE` · `FRIEND`). 탭은 아직 그 값을 읽지 않는다 — A④ 가 입력 화면(사이 켜진 채)으로 잇는다. 탭을 바꾸는 것처럼 쌓지 않는다.
   - 옛 1.0.0 궁합 화면 파일(직접 입력 · 결과 · 랭킹)은 A④ 의 정리(A4-6)까지 두고, 궁합 레이아웃이 탭 첫 화면만 그린다. 그 밖의 `/synastry/**` 는 지금처럼 홈으로 보낸다.
4. **홈이 앱을 켤 때 받아 두는 것은 그대로 둔다** — 나 탭 풀이 상태 · 시기 풀이 상태 · 이번 달. 그 탭을 열면 곧바로 보인다(075 의 4). 홈 화면에는 그리지 않는다.
   - 처음 들어올 때 스플래시는 출생 정보와 오늘의 하늘 카드의 첫 상태까지만 기다린다. 시기 풀이 상태는 기다리지 않는다(홈에 시기 칸이 없다).
5. **소개 세 장의 가운데 장 그림**은 1.0.0 전의 소개(결정 042 의 둘째 장)에 있던 별이 · 하트 카드 둘을 되살린다. 시안 "온보딩 소개 2/3" 의 그림과 같다. 글은 시안대로다.

## 근거
- 소개 기록은 1.0.x 를 켠 모든 기기에 있고 사람 값이 아니라 지워지지 않는다. 서버 계약 없이(102 의 4) 앱만으로 가릴 수 있다.
- "처음 읽은 값" 을 쓰면 1.1.0 이 이번 실행에 적은 소개 기록에 속지 않는다.
- 다 쓰인 풀이로 가리는 셋째 줄은 서버를 기다리지 않고, 틀려도 창의 한 줄일 뿐이다.
- 반쪽 입력 화면을 만들면 A④ 가 다시 쓴다. 누를 곳 없는 줄보다 줄이 없는 편이 덜 헷갈린다.

## 버린 대안
- `byeolmyeong.` 으로 시작하는 기록(받아 둔 풀이 · 출생 정보)으로 가리기: 로그아웃 · 탈퇴하면 지워지고, 1.1.0 에 새로 가입한 사람도 곧 생긴다.
- 업데이트 권유 기록(`byeolmyeong-device.updateAsked.v1`): 권유 창을 본 사람에게만 있다.
- 서버에 앱 버전을 적어 두고 묻기: 서버 계약이 새로 생긴다.
- 셋째 줄을 `GET /entitlements` 가 생길 때까지 미루기: 1.0.0 사용자 대부분이 받은 풀이를 걱정할 때 보여 줄 말이 빠진다.
- 궁합 탭에 직접 입력 줄만 두고 누르면 옛 직접 입력 화면으로: 옛 화면은 사이 넷 · 저장 안 함(104 와 다름)이다.
