# 009. 스플래시 직후 가입을 받고, 구글·애플·카카오 로그인과 만 14세 이상 확인을 둔다

> 상태: 활성 · 결정일 2026-11-11 · 출처: docs/raw/2026-11-11-session-planning-1.0.0.md · docs/decisions/005-google-apple-login.md 를 대체하고, docs/decisions/006-server-side-chart.md 의 "차트 계산 요청은 로그인 없이 받는다"를 대체한다

## 맥락
결정 005 는 입력과 차트를 로그인 없이 쓰고, 해석부터 구글·애플 로그인을 요구했다. 그 뒤 타깃에 10대 후반(만 14세 이상)이 확산 타깃으로 들어왔고(docs/product.md), 궁합 랭킹·조각처럼 계정이 있어야 쌓이는 기능이 늘었다. 만 14세 미만의 개인정보를 받으려면 법정대리인 동의가 필요하다.

## 결정
- 스플래시 다음 화면에서 가입(로그인)을 받는다. 입력·차트를 포함해 모든 화면은 로그인한 뒤에 쓴다. 로그인 없이 열리는 화면은 공유 페이지뿐이다.
- 로그인 수단은 구글·애플·카카오 세 가지다.
- 가입할 때 만 14세 이상인지 확인하고, 만 14세 미만은 가입을 받지 않는다.
- 결정 006 의 나머지(계산은 서버에서 한다)는 그대로다.

## 근거
- 만 14세 확인을 가입 한 번에 끝낸다. 로그인 없이 출생 정보를 받으면 나이 확인 전에 개인정보를 받게 된다.
- 출생 정보가 처음부터 계정에 저장되어 기기 저장 → 계정 저장 옮기기가 필요 없다.
- 10대 확산 타깃은 구글·애플보다 카카오 계정이 익숙하다.
- Apple 은 외부 로그인을 넣은 앱에 애플 로그인도 요구한다. 애플 로그인이 이미 있다.

## 대안
- 결정 005 그대로(해석부터 로그인) — 첫 화면 이탈이 적지만 만 14세 확인 시점이 애매하고, 로그인 전 출생 정보 처리 흐름이 남는다.
- 구글·애플만 — 10대가 가입에서 막힌다.

## 결과·재검토 조건
- 서버의 로그인 없는 차트 계산(`POST /charts`)이 로그인 요구로 바뀐다. 서버 저장소 docs/architecture.md 와 맞춰야 한다.
- 카카오 로그인 앱 등록(카카오 개발자 콘솔)이 사용자 준비 항목에 들어간다.
- [확인 필요] 만 14세 확인 방법: 생년월일 입력으로 확인할지, 카카오 연령대 동의 항목을 쓸지(카카오 쪽 검수가 필요할 수 있다).
- 첫 화면 이탈이 크면 스플래시와 로그인 사이에 소개 화면 2~3장을 둔다. 성공 지표에 "스플래시 → 가입 완료율"을 본다.
