# 109. (1.1.0) 1.0.0 사용자에게는 이메일 · 업데이트 권유 · 광고 푸시 · 새로워진 점 창으로 알리고, 1.0.0 앱의 자세한 풀이 받기는 "업데이트 필요"로 막는다

> 상태: 활성 · 결정일 2026-11-28(1.1.0 기획 때 "7번"으로 미뤄 둔 일 — 소유자 "엉 1번부터 하자" → 세션 안 → "엉 그렇게 하자 광고 푸시도 하자 그럼 그 모달도 있어야겠네")
> - 결정 059(업데이트 두 단계) · 027 의 426 길 · 107(공지사항) · 108(개정 공지)을 쓴다.
> - 시안: 캔버스 "홈 (1.1.0)" 페이지 R1 ~ R3
> - 원본: docs/raw/2026-11-27-session-planning-1.1.0.md 178 ~ 179

## 맥락
- 1.0.0 앱은 결제를 모른다. 1.1.0 서버가 안 산 사람의 받기에 402 를 주면 1.0.0 앱은 일반 오류로 보인다.
- 1.0.0 앱에는 업데이트 권유 창(17)과 업데이트 필요 화면(17-1)이 있고, 글은 앱 안에 있어 바꿀 수 없다.
- 1.1.0 의 공지사항은 1.1.0 앱부터 보인다.

## 결정
1. **출시 전(공지일)**: 약관 · 처리방침 개정 이메일 + 랜딩 공지(108). 유료 전환과 "1.0.0 에서 받은 자세한 풀이는 그대로 무료"를 적는다. 새 기능 홍보 문구는 넣지 않는다(섞이면 메일 전체가 광고성).
2. **출시일 — 업데이트 권유**: 어드민에서 iOS 최신 버전을 1.1.0 으로 올려 1.0.0 앱에 권유 창(17)을 한 번 띄운다. 강제 업데이트(최소 버전)는 올리지 않는다.
3. **1.0.0 앱의 자세한 풀이 받기**: 서버는 1.1.0 미만 앱의 받기 요청에 "업데이트 필요"(426)로 답해 1.0.0 앱의 17-1 화면을 띄운다. 이미 받은 풀이 보기 · 다른 기능은 그대로 된다.
4. **1.1.0 첫 공지글**: 업데이트 갈래 · 알림 없음(107) — "1.1.0 — 궁합 · 새 홈 · 자세한 풀이".
5. **광고 푸시 한 번**: 마케팅 동의자에게만 어드민 "푸시 발송"으로 "(광고) 궁합이 생겼어요 · 연애 · 친구 궁합을 볼 수 있어요. 앱을 업데이트하고 확인해 보세요." + 수신 거부 안내. 1.0.0 앱도 받는다.
6. **새로워진 점 창**: 1.1.0 을 처음 켤 때 한 번, 1.0.0 에서 업데이트한 사람만(새로 깐 사람은 안 본다). 세 줄 — 궁합이 생겼어요 · 홈이 한눈에 보여요 · 받았던 자세한 풀이는 그대로(1.0.0 에서 받은 사람만). 버튼 "닫기" · "궁합 보러 가기"(궁합 탭). 본 것은 기기에 적는다.
7. **App Store "새로운 기능" 글**은 출시 직전에 쓴다.

## 근거
- 법적 개정 공지(이메일)와 홍보(광고 푸시 · 창)를 나눠 광고성 규칙에 걸리지 않게 한다.
- 강제 업데이트 대신 받기만 막으면, 이미 받은 사람은 1.0.0 그대로 써도 불편이 없다.
- 새로워진 점 창은 1.0.0 사용자에게만 보여 새 사용자의 첫 화면을 방해하지 않는다.

## 대안
- 강제 업데이트(최소 버전 1.1.0): 확실하지만 이미 받은 사람까지 막는다.
- 새로워진 점 창 없음: 세션이 처음 권했으나 소유자가 광고 푸시와 함께 "그 모달도 있어야겠네"라고 했다.
- 1.0.0 앱에 결제 없이 계속 무료: 옛 앱으로 유료를 피해 가는 길이 생긴다.

## 결과 · 재검토 조건
- 1.0.0 앱의 17-1 글("이 버전은 더 이상 쓸 수 없어요")은 받기만 막는 상황엔 조금 세다 — 앱 글이라 못 바꾼다. 문의가 오면 최소 버전을 올리는 쪽을 다시 본다.
- 426 을 받기 요청에만 주려면 서버가 앱 버전 머리(헤더)를 읽어야 한다(027 의 길) — 구현 계획 S① 에서 확인.
