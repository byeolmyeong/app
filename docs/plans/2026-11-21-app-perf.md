## 목표
- 무엇을: 처음 여는 사람이 스플래시에서 기다리는 시간과 받는 바이트를 줄인다. 웹이 먼저(가장 무겁다), 네이티브는 재 보고 판단한다.
- 누구를 위해: 처음 들어오는 사람(공유 · 랜딩에서 웹으로) — 스플래시가 길면 첫 화면을 보기 전에 떠난다.
- 끝나면: 아래 "검증" 표의 숫자가 줄어든 것을 같은 조건으로 보인다. 화면 · 동작은 그대로다.

## 측정 방법(같은 조건 전/후가 핵심)
- **웹(로컬, 비교의 기준)**: `npx expo export --platform web --source-maps`(`EXPO_PUBLIC_API_URL=http://localhost:4174`) → 로컬 정적 서버(Vercel 처럼 js · css · html · json · svg · otf 는 brotli, 그림 · woff2 는 그대로, `/x` → `x.html`) + 가짜 서버(세션 401 · 앱 설정만 — 처음 온 사람) → **Lighthouse 12.6.1 모바일 기본값**(느린 4G · CPU 4배 느리게 흉내, 이 맥의 Chrome headless, 깨끗한 프로필) **3회 중앙값**: 점수 · FCP · LCP · TBT · SI · 전송량, 첫 화면 전송 바이트를 글꼴 · JS · 그림 · 그 밖으로. 도구(서버 · 가짜 서버 · 3회 실행)는 작업마다 scratchpad 에 둔다(저장소에 넣지 않음).
  - 로컬 brotli 는 최고 압축(11)이라 Vercel(그때그때 압축)보다 작게 나온다 — 전/후 비교는 로컬끼리, 스테이징은 참고값.
- **웹(스테이징 참고값)**: `https://app.staging.byeolmyeong.com/` 에 같은 Lighthouse 3회.
- **번들 구성**: `source-map-explorer`(scratchpad)로 entry 의 패키지별 크기.
- **네이티브**: `npx expo export --platform ios` 의 Hermes 바이트코드(`.hbc`) 크기 · 함께 실리는 그림/글꼴 크기. 시작 때 기다리는 요청 수와 스플래시가 기다리는 것은 코드로 센다(아래). 차가운 시작 · 목록 · 그림 다시 그리기는 기기 빌드(테스트앱)에서 잰다 — 이 계획의 뒤쪽.

### 스플래시가 기다리는 것(코드)
1. **글꼴 셋**(`useFonts` — 웹은 3.2MB 내려받기, 앱은 4.7MB 읽어 등록)
2. 세션 확인 — 웹 `GET /auth/session`, 앱은 보안 저장소 → (토큰이 있으면) `GET /auth/session`
3. (로그인 전) 소개를 봤는지(AsyncStorage) · 가드가 보낼 곳으로 간 뒤
4. (로그인) 이용 정지 문 `GET /account`(많아야 3초)
5. (로그인한 홈) 홈의 첫 데이터 — 기기의 출생 정보, 없으면 되살리기 `GET /profile` → `POST /charts` + `GET /places`
6. 웹은 최소 0.8초 · 최대 10초, 앱은 최대 5초

### 시작 때 요청(코드로 셈)
- 로그인 · 기기에 데이터 있음: 스플래시가 기다리는 것은 **차례로 2번**(`GET /auth/session` → `GET /account`). 함께 `GET /app-config`. 홈이 뜨면 `GET /account`(**이용 정지 문과 같은 요청을 한 번 더**) · `GET /timing-report` · `POST /day-sky` · `GET /notifications`(+ 앱은 `POST /push/devices`).
- 처음 온 사람(웹 측정에서 본 것): `GET /app-config` · `GET /auth/session` · **`GET /places`**(가드 가림막 아래에서 홈의 출생 정보 입력이 먼저 그려져 곳 목록을 받는다 — 보내질 화면인데 받는 것) · 별이 그림 288KB(소개).
