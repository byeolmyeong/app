# 027. 최소 버전보다 낮은 앱은 "업데이트가 필요해요" 화면으로 막는다(하던 일은 끊지 않는다)

> 상태: 활성 · 결정일 2026-11-12 · 새 결정이다(대체하는 결정 없음). 번호 025 · 026 은 아직 합쳐지지 않은 다른 브랜치가 쓴다.

## 맥락
- 스토어에 나간 옛 버전을 서버가 더 받아 줄 수 없게 될 때(계약이 바뀌거나 문제가 있는 버전) 그 버전을 쓰는 사람에게 업데이트를 받게 할 길이 없었다.
- 소유자가 2026-11-12 에 정했다: 관리자가 플랫폼별 최소 버전을 정하고, 그보다 낮은 앱은 업데이트 화면만 보인다. 다만 하던 일은 끊지 않는다. 급할 때는 관리자가 스위치(`blockNow`)로 서버가 바로 거절하게 한다.

## 결정
- 서버 계약(서버 저장소와 함께 만든다. 이름을 바꾸지 않는다):
  - `GET /app-config` — 세션 없이. 200 `{ ios, android }`, 각각 `{ minVersion: string | null, storeUrl: string | null, message: string | null, blockNow: boolean }`. `minVersion` 은 점으로 나눈 숫자 1~3 마디("1.2.0"), `null` 이면 아무도 막지 않는다. `message` 는 관리자가 적는 안내(그냥 글자).
  - 앱(네이티브만)은 모든 요청에 `X-App-Platform: ios|android` 와 `X-App-Version: <expo 설정의 version>` 을 붙인다.
  - `blockNow` 가 켜져 있고 요청의 버전이 `minVersion` 보다 낮으면 서버는 어느 주소에나 426 `{ "error": "UPDATE_REQUIRED" }` 로 답한다.
- 확인하는 때: 앱이 켜질 때와 앞으로 돌아올 때(AppState 가 active 가 될 때)뿐이다. 쓰는 동안 시간 간격으로 다시 묻지 않는다.
- 내 버전이 내 플랫폼의 `minVersion` 보다 낮으면 막는 화면만 보인다: "업데이트가 필요해요", 관리자의 `message`(없으면 기본 문구), `storeUrl` 을 여는 버튼 하나(`storeUrl` 이 null 이면 버튼 대신 한 줄 안내). 뒤로 가기 · 닫기는 없고 다른 화면에 갈 수 없다.
- 하던 일은 끊지 않는다: 풀이 글 · 심층 리포트 · 궁합 · 궁합 리포트 · 방향성 제시를 만드는 중이거나 방금 받은 결과가 떠 있는 화면, 글을 적어 둔 문의하기 화면은 떠 있는 동안 "바쁨" 을 등록한다. 바쁜 화면이 하나라도 있으면 막는 화면을 미루고, 그 화면에서 나오면(화면이 사라지면) 보인다. 결과는 서버에 저장돼 있어 업데이트해도 잃지 않는다.
  - "나온다" 는 그 화면이 스택에서 빠지는 것이다. 결과 화면 위에 다른 화면(내 차트 등)을 연 동안에는 아직 바쁨이다. 기기에 받아 둔 글을 다시 여는 것은 바쁨이 아니다.
- 급한 길: 어느 호출이든 426 `UPDATE_REQUIRED` 를 받으면 바쁨과 상관없이 바로 막는다. 이 표시는 앱을 끌 때까지 풀리지 않는다.
- 확인하지 못하면 막지 않는다: `GET /app-config` 가 실패했거나(네트워크 · 5xx · 모양이 다름) `minVersion` 이 null 이면 막지 않는다. 한 번 "막는다" 는 답을 받은 뒤의 다시 확인이 실패하면 앞의 답을 그대로 둔다(비행기 모드로 풀리지 않게). 판정은 메모리에만 있어 앱을 새로 켜면 처음부터 다시 묻는다.
- 버전 비교는 마디마다 숫자로 한다(1.10.0 > 1.9.9, 없는 마디는 0). 어느 한쪽이라도 읽을 수 없으면 막지 않는다. 내 버전은 `expo-constants` 의 `Constants.expoConfig?.version` 이다.
- 웹은 막지 않고 버전 헤더도 보내지 않는다(언제나 최신이다). 웹에서는 확인하지 않는다. 가짜 서버(`EXPO_PUBLIC_USE_FIXTURES`)에서는 막지 않는다.
- 막는 화면과 확인은 세션이 필요 없다(로그인 전 · 공개 공유 페이지에서도 동작한다).
- `blockNow` 는 서버가 426 을 줄지 정하는 값이다. 앱은 `/app-config` 의 `blockNow` 를 모양만 확인하고 판정에 쓰지 않는다(급한 길은 426 하나다).

## 버린 대안
- 쓰는 동안 몇 분마다 다시 확인 — 소유자가 고르지 않았다. 켤 때 · 돌아올 때면 충분하고, 급하면 426 이 있다.
- 확인 결과가 나오면 바로 막기 — 1~2분 기다린 글을 받는 순간 끊긴다. 소유자가 "하던 일은 끊지 않는다" 로 정했다.
- 확인하지 못하면 막기 — 서버가 잠깐 아플 때 모든 사람이 앱을 못 쓴다.
- `expo-application` 의 네이티브 버전 쓰기 — 패키지를 더해야 한다. 소유자가 expo 설정의 버전으로 정했다. 남는 걱정: OTA 업데이트(`eas update`)를 쓰면 expo 설정의 버전이 설치된 바이너리와 달라질 수 있다. OTA 를 붙일 때 다시 본다.

## 영향
- `src/lib/app-client.ts`(플랫폼 · 버전), `src/lib/api.ts`(버전 헤더 · `getAppConfig` · 426 알림), `src/features/update/`(새 기능 폴더: 버전 비교 · 판정 · 막는 화면 · 바쁨 등록), `src/app/_layout.tsx`(스택을 `UpdateGate` 로 감싼다), 바쁨을 등록하는 화면(`reading` · `report` · `direction` · `synastry/index` · `synastry/[id]/index` · `synastry/[id]/report` · `settings/inquiry`), `src/content/strings.ts`(`update`).
- 서버: `GET /app-config` 와 426 응답이 필요하다(서버 저장소에서 함께 만든다). [확인 필요] `GET /app-config` 자체는 426 으로 막지 않아야 막힌 앱이 `storeUrl` · `message` 를 받을 수 있다(막아도 앱은 기본 문구로 막는 화면을 보인다 — 버튼만 없다).
- [확인 필요] 네이티브 빌드에서 본 적이 없다(테스트는 모의 객체로만 했다). 출시 전에 실제 기기에서 스토어 열기와 앞으로 돌아올 때의 확인을 본다.
