# 059. 업데이트는 두 단계다 — 새 버전이면 한 번 권하고, 최소 버전보다 낮을 때만 막는다

> 상태: 활성 · 결정일 2026-11-20(소유자 "업데이트는 필수로 하자" → "필수 하지 말자 그냥" → "근데 무조건 업데이트가 필요한 상황도 있잖아" → "그렇게 해서 옮겨줘") · 결정 027 에 "권유" 단계를 더하고 막는 화면의 문구를 바꾼다(027 의 판정 · 바쁨 · 급한 길 426 은 그대로) · 시안: 캔버스 "공통 상태" 17 업데이트 권유 · 17-1 업데이트 필요

## 결정
1. **서버 계약**: `GET /app-config` 의 플랫폼별 값에 `latestVersion: string | null` 을 더한다(어드민에서 정한다). `minVersion` · `storeUrl` · `message` · `blockNow` 는 027 그대로.
2. **권유(17)**: 내 버전이 `latestVersion` 보다 낮고 `minVersion` 이상이면, 앱을 켤 때 홈 위 가운데 창 "새 버전이 나왔어요 · 새 기능이 더해졌어요. 지금 업데이트할까요?" + "나중에" / "업데이트"(`storeUrl`). 같은 `latestVersion` 에는 한 번만 묻는다(물은 버전을 기기에 적어 둔다). 바쁜 화면(027)이 떠 있으면 미룬다. 로그인 전 · 가입 중에는 묻지 않는다.
3. **필요(17-1)**: `minVersion` 보다 낮으면 027 의 막는 화면. 모양은 실패 화면 틀(결정 061): 별 그림 · "새 버전이 나왔어요" · "이 버전은 더 이상 쓸 수 없어요. 업데이트한 뒤에 이어서 볼 수 있어요." · 주 버튼 "업데이트"(글자는 "업데이트하기" 가 아니다). 나중에 하기 · 뒤로 가기는 없다.
4. 막는 일은 "옛 버전이 정말 못 돌아갈 때"(서버 구조를 크게 바꿈 · 보안 · 결제 · 약관)에만 쓴다. 평소에는 `latestVersion` 만 올린다.
5. 웹은 둘 다 하지 않는다(027 그대로, 언제나 최신).

## 근거
- 업데이트를 매번 강제하면 쓰던 사람을 잃는다. 하지만 서버 계약이 깨지는 판에는 막을 길이 있어야 한다 — 두 단계로 둘 다 얻는다.

## 대안
- 늘 강제 — 소유자가 처음 골랐다가 거둬들였다.
- 권유 없이 강제만(027 그대로) — 새 기능을 알릴 길이 없다.

## 결과·재검토 조건
- 서버: 플랫폼 설정에 `latest_version` 칸, 어드민 앱 설정 화면에 입력 칸.
- 결정 027 앞머리에 "문구 · 권유 단계는 059" 표시를 단다.
