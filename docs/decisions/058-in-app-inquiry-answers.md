# 058. 문의는 앱 안에서 주고받는다 — 문의 내역 · 답변 보기를 두고 답장 이메일 칸을 없앤다

> 상태: 활성 · 결정일 2026-11-20(소유자 "이거 앱 안에서 열 수 있도록 해야지") · 결정 024 의 문의하기 중 "답장 받을 이메일" · "보내면 설정으로" · 문의 종류 목록을 대체한다(메일 주소를 앱에 적지 않는 것 · 한 시간 5번 제한 · 적은 것을 기기에 남기지 않는 것은 그대로) · 시안: 캔버스 16-8 문의하기 · 내역 / 새 문의 / 문의를 보냈어요 / 답변 보기

## 맥락
- 024 는 문의를 서버에 보내고 답은 이메일로 받게 했다. 소셜 로그인 이메일을 이미 받고(결정 039) 앱 안에 알림함이 생겨(결정 052) 답도 앱 안에서 볼 수 있다.

## 결정
1. 마이 › 문의하기는 **문의 내역**(16-8)이다: 내 문의 목록(첫 줄 · 상태 "확인 중" / "답변 왔어요" · 날짜) + 맨 아래 주 버튼 "새 문의하기". 비어 있으면 "아직 문의가 없어요".
2. **새 문의**: 종류 칩(오류 · 제안 · 계정 · 기타) + 내용(10~1000자, 글자 수). 이메일 칸은 없다. "답변이 오면 알림으로 알려 드려요. 문의 내역에서 볼 수 있어요." 안내.
3. 보내면 "문의를 보냈어요" → "문의 내역 보기".
4. **답변 보기**: 내 문의 카드 + 별명 답변 카드(날짜). 답은 어드민에서 적는다. 한 문의에 답 하나(더 묻고 싶으면 새 문의).
5. 답이 오면 알림함에 `INQUIRY_ANSWERED`(누르면 그 답변 보기) — 결정 052 의 종류에 더한다. 휴대폰 푸시는 결정 057 을 따른다.
6. 서버 계약(서버 저장소와 함께 만든다): `POST /inquiries { category: BUG · IDEA · ACCOUNT · ETC, body }` · `GET /inquiries` → `[{ id, category, body, status: OPEN · ANSWERED, createdAt, answer?: { body, answeredAt } }]` · `GET /inquiries/{id}`. 어드민: 문의 목록 · 답 적기.

## 근거
- 답을 메일함에서 찾지 않고 앱 안에서 바로 본다. 이메일 칸을 비워 둔 사람에게도 답할 수 있다.

## 대안
- 024 그대로 이메일 답장 — 답이 앱 밖으로 나가고, 이메일을 안 적으면 답할 길이 없다.
- 대화처럼 여러 번 주고받기 — 1.0.0 에는 크다. 한 문의 한 답으로 시작한다.

## 결과·재검토 조건
- 옛 문의(이메일로 받은 것)는 내역에 보이되 답은 "이메일로 보냈어요" 로 둔다(서버가 옛 칸을 그대로 준다).
- 결정 024 · 052 앞머리에 대체 표시를 단다.
