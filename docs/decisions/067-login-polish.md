# 067. 약관 글은 아래에서 올라오고, 로그인을 기다리는 동안 로그인 화면에 머물고, 웹에도 스플래시를 두고, 웹 구글 버튼은 우리 모양으로 그린다

> 상태: 활성 · 결정일 2026-11-20(소유자가 스테이징 웹에서 짚음: "이거 보기하면 지금 밑에서 위로 올라와야하는데 지금 반짝이는데??", "구글 로그인 버튼이 이상해") · 결정 042 의 5 와 결정 044 의 1 중 "웹의 구글은 구글이 그리는 버튼(GIS)" 을 대체한다 · 결정 043 · 044 의 약관 보기(동의하기 · 뒤로)와 결정 034 의 받는 방법(웹 구글은 GIS 의 ID 토큰)은 그대로다 · 시안: 캔버스 보드 1(스플래시) · 5 · 5-2(로그인) · 6-2(약관 보기)

## 맥락
- 약관 "보기"(가입 약관 단계)와 마이의 약관 · 처리방침은 보통 화면처럼 열렸다. 웹의 화면 쌓기(Expo Router SDK 58 의 native stack)는 움직이지 않아 화면이 그냥 바뀌고, 글 화면을 불러오는 동안 빈 바탕이 한 번 보여 번쩍인다.
- 로그인 버튼을 누른 뒤 서버를 기다리는 화면("로그인하는 중이에요" 한 줄)은 시안에 없다. 카카오 웹은 카카오에서 돌아오는 화면(`/auth/kakao`)이 따로 있어 그 화면에 이 줄이 보였다.
- 웹에는 네이티브 스플래시가 없다. 처음 열면 세션 · 소개 기록을 확인하는 동안 빈 바탕만 보였다.
- 웹 구글 버튼(GIS 가 그림)은 구글에 로그인된 브라우저에서 개인 맞춤 버튼(둥근 프로필 · "○○(으)로 로그인" · 이메일 · ⌄)이 되고, 어두운 화면에서 흰 iframe 바탕이 비치고, 높이(최대 40) · 폭(최대 400)이 다른 공급자 버튼(48 · 꽉 찬 폭)과 다르다. GIS 는 이 모양을 바꾸는 옵션이 없다.
- GIS 의 다른 흐름: 토큰 클라이언트는 액세스 토큰, 코드 클라이언트는 인가 코드를 준다(서버가 바꿔야 한다 — 지금 서버 계약 `POST /auth/login` 은 구글 ID 토큰을 받는다). One Tap(`prompt()`)은 사용자가 한 번 닫으면 한동안 뜨지 않는다. GIS 리디렉트(`ux_mode: 'redirect'`)는 서버 주소로 바로 보낸다.
- GIS 버튼은 투명하게 두어도 누름을 받아 구글 창을 연다(헤드리스 Chrome 에서 진짜 GIS 스크립트 · 가짜 클라이언트 ID 로 확인, 2026-11-20).
- Expo Router 문서(SDK 58 "Build custom web modals"): 웹에서 `presentation: 'modal'` 은 보통 화면과 같고, 앞 화면을 남겨 두는 것은 `transparentModal` 이다. `animation`(`slide_from_bottom` 등)은 iOS · 안드로이드에서만 움직인다.

## 결정
1. **약관 글 네 화면(이용약관 · 처리방침 · 개인정보 수집 · 이용 동의 · 마케팅 수신 동의 약관)은 아래에서 올라오는 창으로 연다.** 가입 중 "보기" 와 마이에서 연 것 모두 같다.
   - iOS · 안드로이드: 화면 옵션 `animation: 'slide_from_bottom'` — 화면 전체를 덮고, 닫으면 내려간다. iOS 의 끌어서 닫기는 지금처럼 왼쪽 끝에서 가로로(세로로 끌어 닫기는 긴 글 굴리기와 겹쳐 두지 않는다).
   - 웹: `presentation: 'transparentModal'` 로 앞 화면을 남기고, 글 화면이 스스로 아래에서 올라온다(0.3초). 화면의 뒤로 · 동의하기로 닫으면 내려간 뒤 돌아간다. 브라우저 뒤로 가기는 바로 닫힌다. 주소로 바로 연 글(돌아갈 앞 화면이 없음)은 움직이지 않는다.
   - 바탕은 처음부터 `Colors.paper` 다. 기기의 동작 줄이기가 켜져 있으면 움직이지 않는다.
   - 동의하기 · 뒤로가 하는 일(결정 044 의 3)은 그대로다.
2. **로그인을 기다리는 화면을 따로 두지 않는다.** 버튼을 누른 뒤 서버를 기다리는 동안 로그인 화면(보드 5)에 머물고, 누른 버튼 안의 문구 자리에 작은 돌기, 나머지 버튼은 흐리게 · 누를 수 없게 둔다. 실패하면 지금의 안내 그대로다. 카카오 웹에서 돌아오는 화면처럼 화면이 따로 있어야 하는 곳은 스플래시(결정 3)와 같은 모양이다.
3. **웹에도 스플래시(보드 1)를 그린다.** 밤색 바탕 · 옅은 빛 · 별이와 로고 그림(네이티브 스플래시와 같은 그림, 300)을 가운데에. 처음 열 때 글꼴 · 세션 확인 · 소개를 봤는지 확인이 끝나고 보낼 곳으로 간 뒤에 걷히며, 너무 빨라 깜빡이지 않게 최소 0.8초 보인다. 공유 페이지는 세션을 확인하지 않으므로 글꼴과 최소 시간만 기다린다. 앱(iOS · 안드로이드)은 그 확인이 끝날 때까지 네이티브 스플래시를 그대로 둔다(글꼴만 기다리던 것을 넓힌다).
4. **웹 구글 버튼은 우리 모양으로 그린다(시안 5).** 카카오 · 애플과 같은 공급자 버튼 모양 — 높이 48 · 모서리 12 · 꽉 찬 폭 · 바탕 `#131314` · 테두리 1px `#8E918F` · 왼쪽 G 로고 · 가운데 "Google로 로그인". 로그인은 여전히 GIS 로 받는다: GIS 버튼을 우리 버튼 위에 보이지 않게(투명하게) 겹쳐 누름을 GIS 가 받고, 같은 콜백으로 ID 토큰을 받는다 — 서버 계약은 그대로다. 개인 맞춤 내용(프로필 · 이름 · 이메일)은 화면에 보이지 않는다. GIS 를 불러오지 못하면 버튼을 거두고 실패를 알린다(전과 같다). 최근 로그인 배지(결정 044 의 2)는 우리 버튼에 얹는다. 키보드 포커스와 화면 읽기는 GIS 버튼이 받으므로 그 이름은 구글의 문구다.

## 근거
- 약관 글은 하던 일(가입 · 마이) 위에 잠깐 펼쳐 읽고 닫는 글이다. 아래에서 올라오면 "읽고 돌아간다" 가 보인다.
- 기다리는 동안 다른 화면으로 가면 화면이 두 번 바뀌어 깜빡인다. 누른 버튼에 돌기를 두면 무엇을 기다리는지 그 자리에서 보인다.
- 웹 첫 화면의 빈 바탕은 고장처럼 보인다. 앱과 같은 그림이면 같은 앱으로 읽힌다.
- GIS 를 겹치면 받는 토큰과 서버가 그대로라 바꿀 곳이 버튼 한 파일이다.

## 대안
- 웹 구글은 GIS 버튼 그대로(결정 042 · 044) — 소유자가 이상하다고 했다. 맞춤 버튼의 이메일이 공유 기기에서 보인다.
- 토큰 · 코드 클라이언트 — 서버 계약이 바뀐다.
- 우리 버튼에서 One Tap(`prompt()`) 부르기 — 사용자가 닫은 뒤에는 한동안 아무 일도 일어나지 않는다.
- 구글 OIDC 리디렉트(`response_type=id_token`)로 돌아오는 화면 두기 — 서버 계약은 그대로지만 구글 콘솔에 돌아올 주소를 더하고 화면을 떠났다 와야 한다. GIS 겹치기가 막힐 때의 다음 길로 남긴다.
- iOS `presentation: 'modal'`(아래에서 올라오는 시트) — 위가 비고 앞 화면이 뒤로 물러나 보드 6-2(전체 화면)와 다르다.

## 결과·재검토 조건
- GIS 가 투명한 버튼의 누름을 막게 바뀌면(클릭재킹 방지) 웹 구글 로그인이 멈춘다. 그때는 리디렉트(대안)로 옮긴다. 배포 뒤 스테이징에서 진짜 구글 계정으로 한 번 확인한다.
- 구글이 맞춤 버튼으로 보여 주던 "어느 계정인지" 는 구글 창에서 고른다.
- 웹 브라우저 뒤로 가기로 닫는 약관 글은 내려가지 않고 바로 닫힌다.
- 결정 042 · 044 의 나머지(버튼 문구 · 모양 · 최근 로그인 · 약관 보기의 동의하기)는 그대로다.
