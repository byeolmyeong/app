# 112. 출생 정보 되살리기는 서버에 없을 때(404 NO_PROFILE)만 입력 화면으로, 있는지 알 수 없으면 다시 보기

> 상태: 활성 · 결정일 2026-11-28(소유자 — 버그 묶음 "고쳐", 앱 줄 A2) · 결정 029 의 "되살리지 못하면 막지 않는다: 404 · 네트워크 · 서버 오류 · 모양이 다른 응답 · 차트를 받지 못함 — 어느 것이든 입력 화면" 을 대체한다. 029 의 나머지(언제 부르는지 · 200 이면 되살리는 법 · 하지 않는 때)는 그대로다.

## 맥락
- 029 는 되살리지 못하면 무엇이든 입력 화면을 보였다. 그런데 끊김 · 서버 5xx · 429 · 응답이 멈춤도 404 와 똑같이 "출생 정보가 없는 처음 온 사람" 으로 보였고, 홈이 뜬 동안 다시 묻지 않았다.
- 서버에 출생 정보가 있는 사람이 그 화면에서 조금 다르게(시각 · 곳) 다시 넣으면 `PUT /profile` 이 출생 정보가 바뀐 것으로 보고(`BirthProfileChanged`) 그 계정의 요약 해석 · 나 탭 풀이 · 시기 풀이 · 그날의 하늘 저장분을 지운다(서버 결정 041). 잠깐의 실패가 글을 잃게 만든다.

## 결정
1. 입력 화면은 서버가 "저장한 적 없다" 고 답했을 때(`GET /profile` 404 `NO_PROFILE`)만 보인다. 가짜 서버도 이 답이라 지금처럼 입력 화면이다.
2. 그 밖의 실패 — 끊김 · 서버 오류(5xx) · 429 · `NO_PROFILE` 이 아닌 404 · 모양이 다른 응답 · 401 · 출생 정보는 받았는데 차트를 받지 못함 · 기기에 두지 못함 — 는 입력 화면 대신 공통 상태 화면을 보인다(새 그림 없음, 결정 061 · 065):
   - 인터넷이 되면 "홈을 불러오지 못했어요"(보드 19, `strings.states.loadFail`) · "다시 보기".
   - 인터넷이 끊겼으면 "인터넷에 연결되어 있지 않아요"(보드 20-1, `strings.states.offlineEmpty`) · "다시 시도".
   - 머리(로고)와 아래 탭은 10초가 넘은 때의 19 와 같다. 누르면 홈을 처음부터(기기 읽기 · 되살리기) 다시 한다 — 10초가 넘은 때의 다시 보기와 같은 길.
3. 시각이 있는데 곳이 없는 값(계약에 없다)은 되살릴 수 없으니 지금처럼 입력 화면이다.

## 버린 대안
- 실패하면 몇 번 저절로 다시 묻기 — 서버가 아프면 계속 기다리게 된다. 사람이 누르는 다시 보기 하나면 충분하다.
- 입력 화면을 보이되 "이미 있어요" 경고 — 있는지 모르는 때라 경고할 수 없다.
