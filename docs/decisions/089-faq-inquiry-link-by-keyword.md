# 089. 자주 묻는 질문의 답에 "문의하기" 가 있으면 펼친 답 아래에 문의하기로 가는 링크를 둔다

> 상태: 활성 · 결정일 2026-11-26(소유자 — 테스트앱 빌드 15 피드백) · 결정 028(답은 관리자가 적은 그냥 글자, HTML · 마크다운으로 해석하지 않는다)은 그대로다 · 결정 024 · 058(문의는 앱 안 새 문의로)

## 맥락
- 소유자: "태어난 곳이 목록에 없어요 라고 하면 문의하기로 문의 달라 하고 밑에 바로 갈 수 있는 버튼을 만들어 주는 게 좋지 않을까"
- 답은 관리자가 관리 화면에서 적는 그냥 글자다(결정 028). 질문마다 버튼을 켜는 칸을 서버에 두면 관리 화면 · API · 앱을 모두 바꿔야 한다.
- 2026-11-26 운영 FAQ 열 개 중 답에 "문의하기" 가 든 것은 "문의는 어디로 하나요?" 하나다. 그 답도 문의하기로 가는 길을 안내한다.

## 결정
1. **답에 "문의하기" 라는 말이 있으면, 펼친 답 아래에 "문의하기" 링크를 둔다.** 누르면 새 문의(`/my/inquiries/new`)로 간다. 그 말이 없으면 링크도 없다.
2. **켜고 끄는 것은 관리자의 글이다.** 서버 · 관리 화면은 바꾸지 않는다. 링크를 원하는 답에는 "아래 문의하기로 알려 주세요" 처럼 그 말을 넣는다. 찾는 말은 `strings.faq.inquiryKeyword` 한 곳에 둔다(1.2.0 영어 때 함께 옮긴다).
3. 링크는 FAQ 화면의 "등록된 질문이 없어요" 아래 링크와 같은 부품(`TextLink`)이다. 답 글과 링크 사이 12, 링크 아래 16. 링크도 잰 칸 안이라 펼치고 접는 높이에 함께 들어간다.
4. 문의 종류는 미리 고르지 않는다. 지금 종류(오류 · 제안 · 계정 · 기타)에 출생 정보가 따로 없어, 사람이 고르게 둔다.

## 근거
- 글만으로 켜고 끄면 출시 직전에 서버 · 관리 화면을 건드리지 않는다. 관리자는 지금 하던 대로 답을 고친다.
- "문의하기" 를 안내하는 답에 링크가 붙는 것은 읽는 사람의 기대와 같다.

## 대안
- 질문마다 "문의 버튼" 칸(서버 · 관리 화면 · API) — 가장 분명하지만 세 저장소를 바꾼다. 1.1.0 에서 FAQ 를 다시 볼 때 고른다.
- 질문 글이 "태어난 곳" 일 때만 — 관리자가 질문을 고치면 깨진다.

## 결과·재검토 조건
- 운영 · 스테이징의 "태어난 곳이 목록에 없어요" 답에 "문의하기" 를 넣어야 링크가 보인다. 글은 소유자가 관리 화면 › FAQ 에서 고친다.
- 다른 답에서 "문의하기" 를 링크 없이 쓰고 싶어지면, 그때 질문마다의 칸(대안 1)으로 간다.
