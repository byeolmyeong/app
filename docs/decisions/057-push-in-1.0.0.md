# 057. 휴대폰 푸시를 1.0.0 에 넣고, 오늘의 하늘 아침 알림은 켠 사람에게만 받는 시간에 보낸다

> 상태: 활성 · 결정일 2026-11-20(소유자 "넣는다" — 계획 인터뷰) · 마이 시안에서 소유자가 "여기 알림에 그거 있어야지"(오늘의 하늘 알림)라고 해 마이 알림(16-2)에 켜기/끄기 · 받는 시간을 그렸다 · 결정 051 의 4("1.0.0 에는 켜고 끄기를 두지 않는다, 푸시가 생길 때") · 052 의 "1.0.0 에는 휴대폰 푸시가 없다" · 질문 · 답 7번(docs/raw/2026-11-20-session-owner-qna-home-me-timing.md)과 부딪힌다 · 시안: 캔버스 16-2 · 16-3

## 맥락
- 시안 마이 알림(16-2)은 오늘의 하늘 알림 · 받는 시간 · 이벤트 · 혜택 알림이고, 풀이 알림은 "늘 보낸다" 로 정했다. 문의 답변도 알림으로 알린다(결정 058). 이 화면은 휴대폰 푸시가 있어야 뜻이 있다.
- 같은 날 앞선 답(7번)은 "1.0.0 엔 푸시 없음 — 오늘의 하늘은 열 때 만들고, 알림은 푸시가 생길 때" 였다.

## 결정
1. 1.0.0 에 휴대폰 푸시(Expo 푸시 → APNs · FCM)를 넣는다. 웹은 푸시를 보내지 않는다(웹은 앱 안 알림함만).
2. 보내는 것: 풀이 완성(별명 · 나 탭 풀이 · 시기 풀이 — 늘) · 문의 답변(늘) · 오늘의 하늘(켠 사람에게만, 받는 시간에) · 이벤트 · 혜택(마케팅 수신 동의한 사람만, 결정 039).
3. 오늘의 하늘 알림을 켠 사람은 서버가 받는 시간 조금 전에 그날 것을 미리 만들어 둔다(결정 051 의 "열 때 만든다" 는 끈 사람에게 그대로). 비용은 켠 사람 수에 묶인다.
4. 기본값: 오늘의 하늘 알림은 가입 때 받은 "[선택] 푸시 알림 받기" 동의를 따른다 · 받는 시간 오전 8:00.

## 대안
- 1.0.0 에 푸시 없음(051 그대로) — 마이 알림(16-2)은 이벤트 · 혜택 알림(마케팅 동의) 한 줄만 남고 마이 첫 화면의 알림 줄 오른쪽 "오전 8:00" 은 없앤다. 풀이 완성 · 문의 답변은 앱 안 알림함으로만 알린다. 쓰는 중 화면의 "앱을 닫아도 괜찮아요" 는 그대로 둘 수 있다(알림함).
- 푸시는 넣되 오늘의 하늘 아침 알림만 뒤로 — 받는 시간 · 미리 만들기가 빠져 서버 일이 줄어든다.

## 결과·재검토 조건
- 서버에 기기 토큰 등록 · 보내기 · 받는 시간 스케줄러 · 미리 만들기, 앱에 권한 요청 · 토큰 등록 · 알림 눌렀을 때 이동, 어드민에 이벤트 알림 보내기가 생긴다. 결정 051 · 052 앞머리에 대체 표시.
- 앱은 `expo-notifications` 를 더하므로 새 개발 빌드가 필요하다. APNs 키 · FCM 설정은 소유자가 EAS 에 넣는다.
