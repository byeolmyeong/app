# 인스타그램 스토리 공유 · 이미지 저장 — 공유 카드 "나의 별자리"

> 상태: 제안(문서만 — 소유자 2026-11-19 "그 기능을 만들어야 하는데 문서만 만들어놓자", 구현은 승인 뒤) · 기준 develop `b2c4a13` · 브랜치 `docs/instagram-story-share` · 시안: 캔버스 https://claude.ai/artifact/Rt33TzPSEe4PdxNRCej3xT 의 "나" 페이지(공유 시트 · 앱 / 휴대폰 웹 / 컴퓨터 웹, 공유 카드 "나의 별자리")

## 목표
- 무엇을: 공유 시트에서 "인스타그램 스토리 공유"를 누르면 사용자 폰의 인스타그램 앱이 열리고, 스토리 편집 화면에 공유 카드가 배경으로 깔린다. "이미지 저장"은 앱이면 사진 앱(갤러리)에, 웹이면 파일로 저장한다.
- 누구를 위해: 결과를 스토리에 올리고 싶은 사람(확산 타깃 10대 후반 포함, docs/product.md).
- 끝나면: 앱(iOS · Android)의 공유 시트는 버튼 둘(인스타그램 스토리 공유 · 이미지 저장), 웹(휴대폰 · 컴퓨터)은 이미지 저장 하나. 카드는 시안의 "나의 별자리" 한 장이다.

## 결정된 전제
- 결정 025(공유 카드 · 공유 페이지, 이미지 9:16), 036(별이와 함께 — 이 계획이 바꾼다), 033(어두운 디자인), 034(개발 빌드에서만 되는 네이티브 모듈).
- 지금 코드: `src/features/share/share-actions.ts` 는 앱에서 카드를 1080×1920 PNG 로 찍어(`react-native-view-shot`) 기기 공유 창(`expo-sharing`)에 넘기고, 링크는 `Share.share` 로 보낸다. `share-actions.web.ts` 는 `html2canvas-pro` 로 PNG 를 내려받고 링크를 복사한다. 시트는 `share-entry.tsx`.

## 알아본 것 (외부 · 2026-11-19)
- 인스타그램 "Sharing to Stories": iOS 는 `instagram-stories://share` 주소에 앱 ID 를 붙여 열고 배경 이미지를 붙여넣기 보드로 넘긴다. Android 는 인텐트 `com.instagram.share.ADD_TO_STORY` 에 이미지 주소와 앱 ID 를 넣는다. **2023-01 부터 Meta(Facebook) 앱 ID 가 필수**이고, 없으면 인스타그램이 "이 앱은 스토리 공유를 지원하지 않는다"는 오류를 띄운다. 마지막 "올리기"는 사용자가 누른다(앱이 대신 올릴 수 없다). 출처: https://developers.facebook.com/docs/instagram-platform/sharing-to-stories , https://developers.facebook.com/blog/post/2022/10/10/introducing-important-update-to-Instagram-sharing-to-stories/
- 웹은 인스타그램 스토리 편집 화면을 열 수 없다(그래서 웹은 저장만 — 소유자 결정).
- [확인 필요] iPhone 사파리에서 내려받은 이미지는 사진 앱이 아니라 "파일" 앱의 다운로드로 간다. Android 크롬은 다운로드 폴더(갤러리에 보임).
- [확인 필요] 앱 ID 만으로 되는지, Meta 쪽 앱 검수가 필요한지. 정확한 매개변수 이름(`source_application` 등)은 구현 때 공식 문서로 다시 확인한다.

## 내 결정 (묻지 않고 고른 기본값)
- 앱의 이미지 저장은 사진 앱에 넣는다(`expo-media-library`, 저장 권한만). 거절하면 "설정에서 사진 접근을 허용해 주세요" 안내와 설정 열기.
- 인스타그램이 없거나 스토리 열기에 실패하면 지금처럼 기기 공유 창(`expo-sharing`)으로 이미지를 넘긴다(사용자가 다른 앱을 고를 수 있게).
- 스토리 연결 방법은 태스크 3 에서 정한다: 후보 ① `react-native-share`(InstagramStories 지원), ② 작은 Expo 모듈 + config plugin 을 직접. SDK 58 호환 · 유지 상태 · 앱 크기를 비교한다.
- 앱 ID 는 `.env` 의 `EXPO_PUBLIC_META_APP_ID` → `app.config.ts` 에서 읽는다(앱 ID 는 비밀이 아니지만 문서에는 이름만 적는다). 없으면 스토리 버튼을 숨기고 저장만 보인다.
- iOS 는 `LSApplicationQueriesSchemes` 에 `instagram-stories`, Android 는 `<queries>` 에 `com.instagram.android`(Android 11+ 패키지 공개 범위) — config plugin 으로 넣는다(손으로 `ios/` · `android/` 를 고치지 않는다).
- 카드 이미지는 지금처럼 1080×1920 PNG. 스토리 배경으로 그대로 쓴다.
- 링크 공유를 없애도 공유 페이지(`/s/<식별자>`)와 `POST /shares` 는 그대로 둔다(다른 카드 · 나중의 링크 스티커에 쓸 수 있다). 시트에서 버튼만 뺀다.

## 범위 밖
- 스토리 링크 스티커 자동 첨부(사용자가 인스타그램에서 직접 붙인다). 피드 · 릴스 · 카카오톡 전용 버튼.
- 다른 카드 셋(궁합 점수 · 랭킹 TOP 3 · 다음 변곡점)의 새 디자인 — 그 화면 시안 때. 이 계획은 요약(별명) 카드만 바꾸고, 나머지 카드는 지금 모양 그대로 새 시트에서 저장 · 스토리 공유만 된다.
- "내 별명" 화면의 공유 아이콘 자리(화면 계획이 맡는다). 웹 공유 페이지의 모양.

## 전역 제약
- Expo SDK 58 · `npx expo install` 만. 네이티브 모듈이 늘어나므로 **개발 빌드와 스토어 빌드를 다시** 만든다(결정 034 · 041 테스트앱).
- 색 · 글자 · 간격은 `src/constants/theme.ts`, 문구는 `src/content/strings.ts` 에서만(골든 룰).
- 카드 · 로그 · 분석 이벤트에 출생 정보(생년월일 · 시각 · 장소)를 넣지 않는다. 카드에는 해 별자리 이름과 그림만 들어간다(태스크 1 의 새 결정이 근거).
- 별자리 그림은 서버가 준 해 별자리로 앱이 그린다(`ChartPicture` 재사용). 앱이 별자리를 계산하지 않는다(결정 006).

## 리뷰 초점
1. 앱 ID 가 비어 있는 빌드(로컬 · 테스트앱)에서 스토리 버튼이 숨고 시트가 깨지지 않는가.
2. 인스타그램이 없을 때 사용자가 막히지 않는가(공유 창으로 넘어감).
3. 카드 이미지 · 이벤트 · 로그 어디에도 출생 정보가 없는가.
4. 저장 권한을 한 번 거절한 뒤 다시 눌렀을 때 안내가 같은가(무한 요청 없음).
