# 100. 1.1.0 은 결제 · 궁합(내 궁합 링크까지) · 음악 · 공지사항이다 — 광고는 하지 않고, 방향성 제시는 따로 두지 않으며, 친구창 · 투두 · 그룹 궁합은 1.2.0 이후다

> 상태: 활성 · 결정일 2026-11-27(소유자 "광고, 인앱 결제, 음악 이것만할까" → "C가 나을 것 같은데" → "광고 없애자 그럼" → "아 이걸로하면 되지 뭐"(카카오톡 공유) → "웹없애는 건 나중에 생각하자" → "공지사항도 만들어야할 것 같은데??") · **제품 범위 변경**: docs/product.md 의 1.1.0(광고 · 990원 광고 제거 · 친구창 · 투두 · 그룹 궁합 · 방향성 제시)과 부딪힌다 · 결정 008 · 015 를 대체한다 · 결정 007 · 014 의 "1.1.0" 시기, 014 · 026 의 방향성 부분, 063 의 4 의 웹 진입을 대체한다 · 원본: docs/raw/2026-11-27-session-planning-1.1.0.md

## 맥락
- 2026-11-27 1.0.0 은 iOS 심사 중, 안드로이드는 비공개 테스트 14일 중이다. 1.1.0 기획을 시작하며 문서에 1.1.0 으로 쌓인 것을 다시 봤다: 궁합 v2(063, 제안) · 결과 전 15초 광고와 990원 광고 제거(008 · 015) · 자세한 풀이 유료화(050) · 음악(062 · 069) · 친구창(007) · 투두·조각·레벨업(014) · 그룹 궁합 · 방향성 제시(궁합).
- 몇은 이미 서로 맞지 않는다. 015 의 광고 대상(요약 해석 · 심층 리포트 · 궁합 리포트 · 방향성)은 050(풀이 유료) · 063(궁합은 한 번에 다 만듦) 뒤로 대부분 없다. 008 의 "방향성 VIP" 와 014 의 "리포트는 계속 무료" 는 050 이 뒤집었다. 방향성은 이성 · 미래를 048 · 049 가 없앴고, 궁합 방향성은 063 이 결과 안 "이 사이의 작은 실천" 으로 넣었다.
- 풀이가 유료가 되면 광고를 둘 무료 결과는 별명 · 오늘의 하늘 · 그날의 하늘 · 궁합뿐이다. 사용자는 이제 막 생기기 시작했다(출시 직전 운영 계정 0).
- 1.0.0 의 공유는 링크 없는 이미지(결정 053)라 새 사람이 들어오는 길이 없다.
- 소유자는 안드로이드 출시 뒤 웹을 없앨 생각이 있지만 그 결정은 뒤로 미뤘다.

## 결정
1. **1.1.0 에 넣는 것**
   - **인앱결제 — 자세한 풀이 유료화**(결정 050 그대로): 나 탭 풀이 · 시기 풀이, 따로 · 묶음. 1.1.0 의 유료 상품은 이것뿐이다. 가격 · 묶음 · 출생 정보를 고친 뒤 다시 받기 · 1.0.0 에서 무료로 받은 사람 · 구매 복원 · 환불은 다음 결정(결제 설계)에서 정한다.
   - **궁합 전체**(결정 063 — 1.1.0 계획에서 확정): 직접 입력 · 별 지도 + 전체 순위 · 한 번에 다 만들기 · 지우기 · 공유 카드, 그리고 **내 궁합 링크와 카카오톡 공유**. 궁합은 무료다(014 의 "궁합 리포트는 계속 무료" 그대로).
   - **음악 세 곡**(결정 062 · 069 그대로): 069 의 4 목록을 끝낸다. 음원 셋과 사용권(소유자)이 조건이다.
   - **공지사항**(새 기능): 관리자가 어드민에서 쓰고, 앱은 서버에서 받아 보여 준다(자주 묻는 질문과 같은 틀 — 결정 028). 보이는 곳(마이 · 알림함 · 홈)과 푸시 여부는 시안에서 정한다.
2. **광고는 하지 않는다.** 결과 전 15초 광고(015)도, 990원 광고 제거 상품(008)도 없다. 그래서 광고 SDK · 추적 허용 창 · 광고용 데이터 수집 신고도 없다. 제품 분석의 GA4(결정 081 이 "1.1.0 광고 때" 로 미룸)도 광고와 함께 미룬다.
3. **방향성 제시를 따로 두지 않는다.** 이성 · 미래는 이미 없앴고(048 · 049), 궁합은 결과의 "이 사이의 작은 실천"(063 의 2)이 맡는다. 궁합 방향성 화면 `/synastry/<식별자>/direction`(026) · 방향성 VIP(008) · 방향성 유료화(014)는 없다. 서버의 `POST /directions` 는 지우지 않고 앱이 부르지 않는다(055 의 7 과 같은 방식).
4. **1.2.0 이후로 미룬다**: 친구창(007) · 투두·조각·레벨업과 대표 문구 "조각을 모은다"(014) · 친구끼리 3~5명 그룹 궁합. 투두를 다시 볼 때는 방향성 대신 화면마다 있는 "작은 실천" 을 출발점으로 삼는다.
5. **웹이 있든 없든 같게 기획한다.**
   - 내 궁합 링크를 앱이 없는 사람이 누르면 랜딩(byeolmyeong.com)의 "앱 받기" 페이지 한 장으로 간다: 누가 보냈는지 · 스토어 버튼 · "앱을 받은 뒤 이 링크를 다시 눌러 주세요". 063 의 4 의 "없으면 웹(로그인 → 출생 정보 → 사이 → 결과)" 은 만들지 않는다.
   - 웹 앱이 남아 있는 동안 웹에서 유료 풀이를 누르면 "앱에서 받기" 안내만 보인다(결제는 앱에서만 — 결정 002).
   - 웹을 없앨지 · 언제 없앨지는 따로 결정한다(이 결정의 일이 아니다).
   - [결정 104 가 대체] 안드로이드 앱이 나오기 전에는 안드로이드 · 컴퓨터로 링크를 연 사람을 웹 앱으로 이어 준다(소유자 "웹으로 이어지게 해야지", 2026-11-27). 아이폰은 그대로 앱 받기.
6. **보내기는 카카오톡 공유**(사용자가 자기 카카오톡에서 친구 · 방을 골라 보낸다 — 앱별 쿼터 안에서 무료)가 주 버튼이고, 그 위에 기기 공유 창("다른 곳으로 보내기")을 둔다(063 의 5 그대로). 알림톡 · 친구톡(비즈메시지, 건당 유료)은 쓰지 않는다.
   - [결정 104 가 대체] 보내기는 휴대폰 기본 공유 창("공유하기") 하나다. 카카오톡 공유(메시지 카드)와 "다른 곳으로 보내기"는 쓰지 않는다(소유자 "공유하기로 바꾸자", 2026-11-27).
7. **자를 선**: 만드는 순서는 결제 → 궁합 핵심(직접 입력 · 별 지도 · 결과 · 공유 카드) → 음악 · 공지사항 → 링크 묶음(내 궁합 링크 · 앱 연결 · 앱 받기 페이지 · 카카오톡 공유). 일정이 밀리면 링크 묶음만 1.1.x 로 넘긴다.

## 근거
- 광고: 수익은 보는 사람 수에 비례하는데 지금은 거의 없다. 반면 광고 하나에 SDK · 서버의 시청 확인 · 처리방침과 두 스토어 신고 · 추적 허용 창 · 만 14~18세 맞춤 광고 끄기 · 990원 상품과 구매 복원이 따라온다. 풀이가 유료가 되면 광고는 다시 열 이유(오늘의 하늘 · 그날의 하늘)나 사람을 데려오는 궁합 앞에 붙는다. 빼면 기다릴 때 음악과 광고 소리가 겹치는 문제도 없고, 앱 크기 · 첫 실행 속도와 "추적하지 않음"(결정 040 · 081)을 지킨다.
- 궁합 전체: 결제만 붙이면 무료였던 것을 유료로 바꾸기만 하는 판이 된다. 궁합은 무료로 주는 새 기능이고, 내 궁합 링크는 1.0.0 에 없던 "새 사람이 들어오는 길" 이다.
- 웹 진입을 빼면 궁합 전체에서 가장 큰 일이 빠지고, 나중에 웹을 없애도 다시 고칠 것이 없다.
- 방향성: 쓸 자리가 모두 "작은 실천" 으로 갔다. 따로 두면 글 생성 규칙이 두 벌이 된다(014 의 근거와 같다).
- 친구창은 채팅이 신고 · 차단 · 실시간 서버를 부르고, 투두는 규칙(조각 수 · 레벨 · 주기 · 화면)이 하나도 정해지지 않았다.
- 공지사항: 유료 전환 · 약관 개정 · 새 기능을 앱 안에서 알릴 곳이 지금은 푸시(마케팅 동의자) · 점검 화면뿐이다.

## 대안
- 결제 + 음악만 — 가장 빠르지만 빼앗기만 하는 판이고 새 사람이 들어올 거리가 없다.
- 결제 + 음악 + 궁합 직접 입력판(링크 · 카카오는 1.2.0) — 세션이 처음 권했다. 소유자가 링크까지를 골랐다. 자를 선(7)으로 이 모양으로 낼 길은 남겼다.
- 광고를 015 대로(결과 전 15초), 또는 "보고 열기"(광고를 보면 유료 풀이 칩 하나 맛보기) — 광고 하나에 따라오는 일은 같다. 고르지 않았다.
- 063 원안의 웹 진입 — 웹을 없앨 수 있어 고르지 않았다.

- 다음에 정할 것(1.1.0 기획 순서): ① 결제 설계 — 가격 · 묶음 · 다시 받기 · 1.0.0 수령자 · 구매 복원 · 환불, 약관(유료 조항 · 청약철회) · 처리방침(RevenueCat) 고침 ② 궁합 확정 — 063 을 활성으로, 서버 계약(링크 · 점수 변환 구간 · 알림 종류), 아래 탭 다섯 칸(055 의 2 대체) · 홈 궁합 칸 · 온보딩 소개 세 장 ③ 음악 — 069 의 4 다시 확인 ④ 공지사항 — 보이는 곳 · 푸시 · 1.1.0 보다 먼저(1.0.x) 낼지(먼저 내면 유료 전환을 앱 안에서 미리 알릴 수 있다). 고를 것은 캔버스 비교 시안으로 같이 본다. 그 뒤 docs/release-1.1.0.md · 구현 계획(서버 먼저).
- 광고를 다시 보는 조건: 무료 기능의 월 AI 비용이 결제 수익을 넘거나, 월 활성 사용자가 [확인 필요] 명을 넘을 때. 그때는 새 결정으로 넣는다(008 · 015 를 되살리지 않는다).
- [확인 필요] 카카오톡 공유 쿼터 숫자(카카오 개발자 콘솔 [쿼터]). 쿼터 상향 신청은 2026-04-01 에 닫혔다(재공지 예정). 쿼터와 별개로 한 사람이 짧은 시간에 많이 보내면 잠깐 막힐 수 있다.
- [확인 필요] 앱 받기 페이지와 앱 연결 파일(`apple-app-site-association` · `assetlinks.json`)을 랜딩에 둘지 — 랜딩 main 은 곧 운영이라 합칠 때마다 소유자의 "합쳐" 가 필요하다. 안드로이드 앱 연결에는 앱 서명 키 SHA-256 이 필요하다.
- [확인 필요] iOS 에는 설치 뒤 그 링크로 이어 가는 기본 방법이 없다(Firebase Dynamic Links 종료). 1.1.0 은 "다시 눌러 주세요" 안내로 시작하고, 유료 추적 SDK 는 쓰지 않는다.
