# 088. 처음부터 펼친 이유 상자는 높이 상한(maxHeight)으로 묶고, 다 펼치면 묶음을 푼다

> 상태: 활성 · 결정일 2026-11-26(소유자 — 테스트앱 빌드 14 피드백) · 결정 083 의 2 중 "처음 누르기 전까지만 높이를 묶지 않고, 그 뒤로는 다른 상자와 똑같이(높이를 묶은 채) 움직인다 · 묶지 않음 → 묶음 한 방향만 쓴다" 를 대체한다. 083 의 1 · 3 · 4(어느 이유를 펼치는지 · 작은 지도 · 뼈대)는 그대로다

## 맥락
- 소유자: "내 별명에서 첫번째 것만 펼쳐놓은 상태로 하는 거잖아. 닫았다가 열면 백그라운드 없이 그림이랑 텍스트가 바로 나오고 깨져. 없어졌다가 생겼다가는 잘 돼. 나머지 이렇게 풀이한 이유는 정상적이야." (iOS 테스트앱 빌드 14)
- 처음부터 펼친 상자(결정 083)만 다른 상자와 세 가지가 달랐다.
  1. 내용을 절대 위치가 아니라 흐름 안에 두고 잰다.
  2. 첫 누름 전에는 움직임 스타일에 높이 키가 없다가, 첫 누름에 높이 키가 생긴다(Reanimated 는 빠진 키를 되돌리지 않아 한 방향만 썼다).
  3. 접고 펴는 동안에도 잰 값을 그대로 받는다.
- 다 펼친 뒤에는 높이를 `진행 1 × 잰 높이` 로 묶은 채 잘라내기를 푼다(용어 말풍선이 칸 밖으로 나오게). 그래서 다시 열 때 잰 높이가 0 이면, 상자의 바탕은 접힌 채로 남고 그림과 글만 그 위로 넘쳐 보인다. 소유자가 본 모습과 같다.
- 웹(같은 규칙의 RN Animated)에서는 닫기 → 다시 열기에서 높이가 0 → 368 로 정상이었다(2026-11-26 정적 웹 빌드, 프레임마다 잼). iOS 는 이 맥에서 빌드할 수 없어 그 자리에서 재현하지 못했다. 그래서 위 세 차이를 모두 없앤다.

## 결정
1. **처음부터 펼친 상자(내용이 흐름 안)는 높이(height) 대신 높이 상한(maxHeight)을 묶는다.** 묶지 않을 때는 아주 큰 상한(`RevealShape.freeMaxHeight`)이라 내용이 제 높이를 낸다. 움직임 스타일의 키가 늘 같아(`maxHeight` · `opacity`) 키가 생기거나 빠지는 일이 없다. 다른 상자(내용을 절대 위치로 잰다)는 지금처럼 높이를 묶는다.
2. **다 펼치면 묶음을 푼다.** 펼침이 끝나면(잘라내기를 풀 때) 상한을 다시 아주 크게 둔다. 잰 값이 틀려도 내용이 제 높이를 내고 바탕이 그만큼 덮는다. 접을 때는 다시 묶는다(진행 1 × 잰 높이가 지금 높이라 튀지 않는다).
3. **흐름 안 상자는 묶지 않았을 때만 잰다.** 접고 펴는 동안 눌린 높이를 잰 값으로 삼지 않는다. 다 펼친 뒤 용어 말풍선으로 줄이 길어지면 그때 다시 잰다.
4. 앱(Reanimated, `reason-reveal.tsx`)과 웹(RN Animated, `reason-reveal.web.tsx`)이 같은 규칙이다. 웹 번들에는 지금처럼 Reanimated 를 싣지 않는다. 자주 묻는 질문(같은 부품, 내용은 절대 위치)은 바뀌지 않는다.

## 근거
- 처음과 다 펼친 뒤를 "묶지 않음" 으로 두면, 끝 상태가 잰 값에 기대지 않는다. 바탕이 내용을 덮지 못하는 일이 생길 수 없다.
- 키를 바꾸지 않고 값만 바꾸면 Reanimated 가 빠진 키를 남겨 두는 문제를 피한다.

## 대안
- 첫 누름에 내용을 절대 위치로 옮겨 다른 상자와 똑같이 — React 다시 그리기와 화면 스레드의 높이 묶음이 한 프레임 어긋나면 상자가 잠깐 0 으로 접힌다.
- `height: 'auto'` 로 풀기 — 문자열 값이 Reanimated 를 거쳐 네이티브에 그대로 가는지 이 맥에서 확인할 수 없다. 숫자 상한이 더 안전하다.

## 결과·재검토 조건
- iOS 테스트앱(빌드 15)에서 소유자가 닫기 → 다시 열기를 확인한다. 같은 모습이 남으면 네이티브에서 잰 값을 로그로 보고 다시 본다.
- 상한 값(10만)은 이유 상자의 내용보다 늘 크다. 내용이 이보다 길어질 일은 없다.
