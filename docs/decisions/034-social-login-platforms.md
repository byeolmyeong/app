# 034. 소셜 로그인은 플랫폼마다 공급자의 공식 방법으로 받고, 웹 세션은 서버의 httpOnly 쿠키에 맡긴다

> 상태: 활성 · 결정일 2026-11-18(소유자) · 결정 017 의 "브랜딩 뒤" 를 채운다 · 서버 쪽: 서버 저장소 `docs/decisions/021-social-login-signup-cookie.md` · 계획: docs/plans/2026-11-18-social-login.md

## 맥락
- 결정 009 는 구글·애플·카카오 가입을 스플래시 직후에 받기로 했고, 결정 017 은 브랜딩 뒤로 미뤘다. 앱 이름이 "별명" 으로 정해져 미룰 이유가 없어졌다.
- 소유자 결정(2026-11-18): 애플·카카오·구글 먼저(네이버는 나중), 만 14세는 출생일로 서버가 판정, 웹·iOS·Android 를 한 번에, 웹은 쿠키로 로그인을 유지.
- 서버는 공급자의 ID 토큰(카카오 웹은 인가 코드)을 받아 직접 확인하고, 계정이 없으면 가입권을 준다(서버 결정 021).
- Expo 문서(SDK 58)는 공급자가 주는 라이브러리를 권한다. 구글 라이브러리의 웹 기능은 유료판이고, `expo-apple-authentication` 은 iOS 만 된다.

## 결정
1. **플랫폼별로 받는 방법**

   | 공급자 | 웹 | iOS | Android |
   |---|---|---|---|
   | 구글 | 구글 공식 웹 버튼(Google Identity Services) → ID 토큰 | `@react-native-google-signin/google-signin`(`webClientId`) → ID 토큰 | iOS 와 같음 |
   | 애플 | Apple JS 팝업 → ID 토큰 · authorization code(+ 로그인에 쓴 돌아올 주소) | `expo-apple-authentication` → identityToken · authorizationCode | **두지 않는다** |
   | 카카오 | 카카오 인가 주소로 이동(`scope=openid` — 결정 039 가 `openid account_email` 로 대체) → `/auth/kakao` 로 돌아온 `code` 를 서버에 | 카카오 네이티브 SDK(`@react-native-seoul/kakao-login`) → ID 토큰 | iOS 와 같음 |

2. **웹 세션은 서버의 httpOnly 쿠키 `bm_session` 이다.** 웹은 모든 요청에 `credentials: 'include'` 를 붙이고 로그인·가입에 `cookie: true` 를 보낸다. 앱 코드는 웹에서 세션 토큰을 받지도 두지도 않는다. 앱(iOS·Android)은 지금처럼 기기 보안 저장소 + `Authorization: Bearer`.
3. **가입 흐름**: 스플래시 → 로그인 화면(그 플랫폼에서 되는 공급자 버튼만) → 처음 온 사람은 `/signup`(출생 정보 입력, 결정 020 의 입력 그대로) → 서버가 만 14세를 판정한다. 미만이면 "만 14세 이상만 가입할 수 있어요" 를 보여 주고 로그인 화면으로. 로그인하지 않으면 `/login`·`/auth/*`·`/s/*`(공유 페이지) 말고는 들어갈 수 없다.
4. **로그아웃**: 설정에 둔다. `DELETE /auth/session` 뒤 기기의 토큰을 지우고 로그인 화면으로.
5. **개발용 세션(결정 017)은 그대로다.** `EXPO_PUBLIC_DEV_SESSION=1` 이면 지금처럼 자동으로 들어간다. 소셜 로그인 흐름은 이 값을 끄고 확인한다.
6. **공급자 ID 는 비밀이 아니다.** `EXPO_PUBLIC_*` 환경 변수로 받고, 빌드 설정에 들어가는 값(구글 iOS URL scheme, 카카오 네이티브 앱 키)은 `app.config.ts` 가 `app.json` 위에 얹는다. 번들 ID·안드로이드 패키지는 `com.byeolmyeong.app`(도메인 `byeolmyeong.com` 을 거꾸로).
7. 이번에 넣지 않는 것: 소개 화면 2~3장(결정 009 는 "첫 화면 이탈이 크면"), 약관·개인정보 처리방침 동의 화면(문안이 자리표시), 네이버, nonce.

## 근거
- 공급자의 공식 방법이 가장 덜 깨진다. 카카오 네이티브 SDK 는 카카오톡 앱으로 바로 로그인한다(10대·20대 타깃에 가장 짧은 길).
- 웹의 구글은 공식 웹 버튼이 무료이고 ID 토큰을 바로 준다. 카카오 웹은 카카오가 토큰 요청을 서버에서 하라고 해서 코드만 받는다.
- 안드로이드 애플: App Store 심사 지침 4.8 은 iOS 앱에만 걸린다. 안드로이드에서 애플 로그인을 하려면 서버를 거치는 웹 방식(돌아올 https 주소 · Services ID)이 더 필요하다.
- 웹 쿠키: 웹에는 기기 보안 저장소가 없다. 브라우저 저장소는 화면에 끼어든 코드가 토큰을 읽을 수 있고, 메모리에만 두면 새로고침마다 로그인이 풀린다.

## 대안
- 셋 다 `expo-auth-session`(브라우저 방식) — 한 가지 코드지만 카카오톡 앱 로그인이 안 되고, 카카오·애플은 돌아올 https 주소와 서버 경로가 더 필요하다.
- 구글 라이브러리 유료판(웹 포함) — 웹 하나 때문에 돈을 쓴다.
- 안드로이드에도 애플 — 위 근거의 비용. 요청이 생기면 서버 리디렉트 경로를 더해 붙인다.

## 결과·재검토 조건
- 네이티브 라이브러리가 들어오므로 Expo Go 로는 로그인을 시험할 수 없다. EAS 개발 빌드가 필요하다.
- 애플로 가입한 사람이 안드로이드로 옮기면 그 기기에서는 들어올 수 없다(웹·아이폰은 된다).
- 애플 웹은 https 주소가 있어야 한다(애플은 localhost 를 받지 않는다) — 스테이징(`staging.byeolmyeong.com`)이 뜬 뒤 확인한다.
- 웹 앱과 서버는 같은 도메인 아래여야 쿠키가 간다(호스팅: 서버 결정 020 의 주소가 맞는다).
- 카카오 RN 라이브러리가 SDK 58 · 새 아키텍처에서 안 되면 앱도 카카오 웹 방식(인가 코드)으로 바꾼다 — 서버는 이미 받는다.
