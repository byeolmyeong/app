# 042. 가입은 약관 → 닉네임 · 프로필 → 출생 정보의 단계로 받고, 소개는 처음 한 번만, 로그인 버튼은 공급자 가이드를 따른다

> 상태: 활성 · 결정일 2026-11-19(소유자 "시안대로 해 · 바로 시작해") · 결정 039 의 3(가입 화면은 한 화면 · 닉네임 1~20자 · 중복 허용)을 대체한다 · 결정 034 의 3(가입 흐름)과 7 의 "소개 화면 · 약관 동의 화면은 넣지 않는다" 를 대체한다 · 결정 020 의 2(시각 "모름" 이면 태어난 곳을 묻지 않는다) 중 앱 입력만 대체한다 · 시안: 피그마 https://www.figma.com/design/PNrWFsXHhF8crQkLA3SYBn · 계획: docs/plans/2026-11-19-onboarding-design.md

## 맥락
- 결정 039 는 닉네임 · 출생 정보 · 마케팅 동의를 가입 화면 한 장에 모았다(폴짝의 화면 방식). 결정 034 는 소개 화면과 약관 동의 화면을 미뤘다.
- 소유자가 온보딩 시안(피그마 보드 20개)을 고치며 정했다(2026-11-19): 스플래시 → 소개 3장 → 로그인 → 약관 동의 → 닉네임 · 프로필 → 출생 정보 → 별명 짓는 중. 한 단계에 한 가지만 묻는다.
- 정보통신망법 제50조: 광고성 정보는 수신자의 명시적 사전 동의(선택)를 따로 받아야 한다. 야간(21~08시) 광고 전송은 별도 동의가 필요하다.
- 공급자 버튼 가이드: 카카오(노랑 `#FEE500` · 심볼 · "카카오 로그인"), 구글(다크 `#131314` · 테두리 `#8E918F` · 가이드 문구 "Google 계정으로 계속하기" — 앱이 그리는 버튼은 소유자가 다른 버튼과 같은 꼴 "Google로 계속하기" 를 골랐다(2026-11-19)), 애플 HIG(흰 바탕 · 검정 로고와 글자, 제목 글자는 버튼 높이의 43%).

## 결정
1. **가입은 단계식이다.** 로그인 → `/signup/terms`(약관, 진행 1/3) → `/signup/nickname`(닉네임 · 프로필, 2/3) → `/signup/birth`(출생 정보, 3/3) → 별명 짓는 중 → 풀이 글. 앞 단계 값은 메모리(가입 초안)에만 두고 마지막 "내 별명 읽기" 에서 `POST /auth/signup` 한 번으로 보낸다. 앞 단계를 건너뛰고 들어오면 빠진 단계로 돌려보낸다.
2. **약관 동의 항목**: 모두 동의 + [필수] 이용약관 · [필수] 개인정보 수집 · 이용 · [선택] 푸시 알림 받기 · [선택] 마케팅 정보 수신(앱 푸시 · 이메일). 필수 둘이 켜져야 다음으로 간다. 선택은 기본 꺼짐이고 "모두 동의" 만 넷을 한 번에 켠다. 야간 광고는 보내지 않으므로 야간 동의는 받지 않는다. 동의한 약관 · 처리방침의 버전(`src/content/legal-versions.ts`)을 함께 보낸다. 푸시는 이번엔 동의 여부만 보낸다(운영체제 권한 · 기기 토큰은 푸시 기능 계획).
3. **닉네임**: 앞뒤 공백을 뗀 한글(완성형 가~힣) · 영문만 2~10자, 숫자 · 공백 · 기호 안 됨, 한글과 영문은 섞어도 된다. **중복 안 됨**(영문 대소문자는 같은 이름). 판정은 서버이고 앱은 같은 규칙으로 먼저 안내한다. 중복은 "다음" 을 누를 때 한 번 묻는다(`POST /auth/nickname-check`) — 칠 때마다 묻지 않는다.
4. **프로필**: 브랜드 그림으로 만든 8종(원본 `assets/brand/avatar-1~8.svg`) 가운데 하나를 닉네임 단계에서 고른다. 처음엔 하나를 무작위로 골라 둔다. 화면에는 "프로필" 이라 쓰고 그림 이름은 보이지 않는다(화면 읽기 이름만).
5. **로그인 버튼**: 공급자 가이드의 색 · 문구 · 로고를 바꾸지 않는다. 셋 다 높이 48 · 모서리 12, 로고는 왼쪽 16 의 같은 세로줄, 문구는 버튼 가운데, **글자는 셋 다 16px**(굵기 500). 애플의 "제목 = 높이의 43%(20.5)" 만 소유자가 통일을 골라 벗어난다. iOS 애플은 시스템 버튼 대신 이 모양으로 그리고 `signInAsync` 를 부른다. 웹의 구글은 구글이 그리는 공식 버튼(GIS)을 그대로 쓴다 — 높이(최대 40)와 글자를 바꿀 수 없어 웹에서만 조금 작다. 안드로이드는 애플 버튼이 없다(결정 034). 로그인 화면 아래 안내 문구(만 14세 · 약관)는 두지 않는다.
6. **소개 3장은 앱을 처음 받아 처음 켰을 때 한 번만** 보인다. 소개가 처음 뜨는 순간 본 것으로 기기 저장소(AsyncStorage — 앱을 지우면 함께 지워진다. 키체인 `expo-secure-store` 는 앱을 지워도 남아 쓰지 않는다)에 적는다. 로그아웃 · 탈퇴 · 세션 만료 뒤에도 다시 보이지 않고, 로그인한 사람에게는 보이지 않는다. 저장소를 읽지 못하면 소개를 건너뛴다.
7. **출생 정보**: 시각 "모름" 은 칸 이름 줄 오른쪽의 작은 체크다. 시각을 몰라도 태어난 곳 칸은 그대로 받는다(결정 020 의 "칸이 사라진다" 대체). 서버는 시각이 `null` 이면 `placeId` 를 읽지 않으므로 그때는 보내지 않는다(서버 계약 그대로). 태어난 곳은 아래에서 올라오는 시트에서 고른다: 맨 위 "동네 이름으로 찾기" 검색, 아래 시 · 도 칩 → 시 · 군 · 구 목록(DESIGN.md 원칙 2 의 "화면을 가득 채우는 고르기 화면" 대체). 목록은 서버가 준 것만 쓴다.
8. **별명 짓는 중**: 별이가 둥실 떠 있고 뒤 빛 · 궤도 점 · 반짝임이 움직이며 안내 문구 셋이 돌아가며 바뀐다. 기기의 "동작 줄이기" 가 켜져 있으면 멈춘 첫 장면과 첫 문구만 보인다(결정 035 의 움직임 예외를 넓힌다).

## 근거
- 한 화면에 칸이 넷을 넘으면 처음 온 사람이 어디부터 채울지 망설인다. 단계마다 하나씩이면 진행 막대로 남은 양이 보인다.
- 가입 초안을 메모리에만 두면 가입권(1회용)을 한 번만 쓰고, 중간에 나가도 계정이 반쯤 생기지 않으며, 공유 기기에 개인정보가 남지 않는다.
- 공급자 가이드를 따르면 심사 · 브랜드 지적이 줄고 사용자가 버튼을 바로 알아본다. 글자 크기 통일은 세 버튼이 한 묶음으로 보이게 하려는 소유자 선택이다.
- 닉네임 중복 확인을 "다음" 에서 한 번만 하면 요청이 적고 남의 닉네임을 하나씩 떠보기 어렵다.

## 대안
- 가입 한 화면 유지(결정 039) — 소유자가 시안에서 단계식을 골랐다.
- 애플 버튼은 시스템 버튼(`AppleAuthenticationButton`) — 글자 크기를 다른 둘과 맞출 수 없다.
- 소개를 로그아웃할 때마다 다시 보이기 · 키체인에 기록 — 같은 사람에게 여러 번 보이거나, 앱을 지우고 다시 받아도 안 보인다.
- 시각을 모르면 태어난 곳을 묻지 않기(결정 020) — 소유자가 칸을 그대로 두기를 골랐다.

## 결과·재검토 조건
- 서버가 닉네임 · 약관 버전 · 프로필을 필수로 받는 배포와 이 앱 배포는 같은 날이어야 한다(옛 가입 화면은 400).
- 애플 심사에서 버튼 글자 크기를 지적받으면 애플만 43%(20.5)로 되돌린다.
- 결정 039 의 나머지(공급자에서 이메일만 필수, 마이의 닉네임 · 이메일 · 동의 스위치, 처리 결과 알림)는 그대로다.
- 약관 개정 때 다시 동의받기, 운영체제 푸시 권한 · 토큰은 따로 계획한다.
