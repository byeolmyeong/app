# 029. 기기에 출생 정보가 없으면 서버에 저장된 것으로 되살린다(기기의 것이 있으면 건드리지 않는다)

> 상태: 활성 · 결정일 2026-11-12 · 새 결정이다(대체하는 결정 없음). "출생 정보와 차트는 기기에 보관하고 다시 열 때 보관본을 쓴다" 는 그대로이고, 기기가 비어 있을 때의 길만 더한다.

## 맥락
- 출생 정보와 차트는 기기에만 있다(`byeolmyeong.birth.v1`). 서버에도 출생 정보가 있지만(`PUT /profile`) 앱은 읽지 않았다. 그래서 새 기기에서 로그인하거나 앱을 지웠다 다시 깔면 출생 정보를 처음부터 다시 넣어야 했다.
- 소유자가 2026-11-12 에 정했다: 돌아온 사람은 다시 입력하지 않는다.

## 결정
- 서버 계약(이미 있는 것을 읽는다. 이름을 바꾸지 않는다): `GET /profile` — 세션 필요. 200 `{ date, time | null, placeId | null }`, 저장된 것이 없으면 404 `NO_PROFILE`. 시각 "모름" 이면 `placeId` 는 `null` 이다(결정 020).
- 언제: 홈(`/`)에서 기기 저장소를 읽었는데 출생 정보가 없고, 세션 확인이 끝나 세션 토큰이 있을 때 `GET /profile` 을 한 번 부른다(홈이 뜬 동안 한 번. 스스로 다시 부르지 않는다).
- 200 이면 기기의 보관본을 다시 만든다:
  - 차트는 입력 화면과 같은 `POST /charts` 로 그 출생 정보의 것을 받는다(앱은 계산하지 않는다. 결정 006).
  - 태어난 곳의 이름은 `GET /places` 목록에서 `placeId` 로 찾는다. 찾지 못하면(목록을 받지 못했거나 그 식별자가 없으면) 실패로 치지 않고 식별자만 두고 이름은 비운다 — 출생 정보 줄은 곳 없이 보이고 입력 칸은 고르기 전의 안내를 보인다. 시각 "모름" 이면 곳이 없다.
  - 입력 화면이 쓰는 것과 같은 보관 함수(`saveBirth`)로 기기에 두고, 입력 화면 대신 홈(카테고리)을 보여 준다. `PUT /profile` 은 다시 하지 않는다(서버의 값을 받은 것이다).
- 확인하는 동안(세션 확인 포함)에는 입력 화면 대신 "불러오는 중이에요" 한 줄을 보여 준다(입력 화면이 잠깐 비쳤다가 바뀌지 않게).
- 되살리지 못하면 막지 않는다: 404 · 네트워크 · 서버 오류 · 모양이 다른 응답 · 차트를 받지 못함 — 어느 것이든 지금처럼 입력 화면을 보여 준다. 사용자가 직접 넣는 길은 언제나 열려 있다.
- 하지 않는 때: 기기에 출생 정보가 이미 있으면 부르지 않는다(기기의 것이 이긴다. 조용히 덮어쓰지 않는다). 세션이 없으면 부르지 않는다. 가짜 서버(`EXPO_PUBLIC_USE_FIXTURES`)는 서버를 부르지 않고 "저장된 것이 없다"(404 `NO_PROFILE`)로 답한다. 공유 페이지(`/s/…`)는 홈이 아니어서 하지 않는다.
- 풀이 글 · 리포트 · 방향성 제시는 따로 되살리지 않는다. 그 화면들이 이미 서버에 묻고, 서버는 저장해 둔 글을 준다.
- 계정을 지우면 기기와 세션이 비고 서버에도 출생 정보가 없다 → 입력 화면이 보인다(지금과 같다).
- 받은 출생 정보는 로그에 남기지 않는다.

## 버린 대안
- 기기에 있어도 서버의 값으로 맞추기 — 기기에서 방금 바꾼 값이 조용히 바뀐다. 두 값이 다를 때 어느 쪽이 맞는지 앱은 모른다.
- 모든 화면(풀이 · 궁합 등)에서 되살리기 — 그 화면들은 출생 정보가 없으면 홈으로 보내는 안내를 이미 보여 준다. 한 곳(홈)이면 충분하다.
- 차트를 서버가 `GET /profile` 에 함께 주기 — 계약을 바꿔야 한다. `POST /charts` 가 같은 입력에 같은 차트를 준다.
- 곳 이름을 찾지 못하면 되살리기를 실패로 치기 — 이름은 보여 주는 글자일 뿐이고 계산에는 식별자만 쓴다.

## 영향
- `src/lib/api.ts`(`getProfile`), `src/features/chart/`(되살리기 `restore-birth.ts` · 훅), `src/app/index.tsx`(확인하는 동안의 한 줄), `src/content/strings.ts`.
- 지금의 개발용 로그인(결정 017)은 모든 기기가 한 개발 계정을 쓴다. 그래서 웹에서 브라우저 저장소를 비우면 이제 입력 화면 대신 개발 계정의 출생 정보가 되살아난다. 의도한 동작이다(소셜 로그인이 붙으면 계정마다 제 것이 온다).
- 웹은 세션 토큰을 보관하지 않아 열 때마다 세션을 새로 받는다. 그동안(짧게) "불러오는 중이에요" 가 보인다.
- [확인 필요] 실제 서버 · 기기에서 본 적이 없다(테스트는 모의 객체로만 했다).
